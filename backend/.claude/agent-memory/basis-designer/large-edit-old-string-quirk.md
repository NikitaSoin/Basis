При редизайне сайдбара Ассистента (2026-07-26) один Edit-вызов с old_string на ~150 строк
CSS (несколько правил подряд, скопированных из Read-вывода) вернул «String to replace not
found in file», хотя python-проверка (`old_string in content`) на том же тексте
подтверждала точное совпадение символ-в-символ (кириллица, длинные тире и пр. — не в этом
дело). Разбивка ТОГО ЖЕ diff на 3-4 меньших Edit-вызова (каждый — одно-два CSS-правила,
30-60 строк) сработала с первого раза на каждом куске.

**Why:** причина не установлена (не кодировка, не whitespace — проверено побайтово через
Python). Похоже на лимит/сбой сопоставления самого инструмента на очень длинных
old_string, а не ошибку в содержимом.

**How to apply:** если Edit возвращает «not found» на длинном (100+ строк) old_string,
который ты только что скопировал из Read — НЕ трать время на поиск невидимой опечатки
(лишний пробел, другой дефис и т.п.). Сразу пробуй тем же содержимым, но 3-4 меньшими
Edit-вызовами по одному-два CSS-правила/JSX-блока за раз. Если нужна диагностика —
`python3 -c "print(old_string in open(path,encoding='utf-8').read())"` быстро подтверждает,
что дело не в тексте.
