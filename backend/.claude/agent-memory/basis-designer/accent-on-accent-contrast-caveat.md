Токены (`tokens.css`): светлая тема `--accent:#C97A4A` (медь) + `--on-accent:#FFFFFF`;
тёмная тема `--accent:#DB9463` (светлее медь) + `--on-accent:#0B1220` (тёмно-синий, не
белый — специально, чтобы текст читался на посветлевшем в тёмной теме акценте).

Проверено расчётом (2026-07-26, при редизайне сайдбара Ассистента): пара
"white-on-#C97A4A" (светлая тема) даёт контраст **≈3.3:1** — ниже WCAG AA для обычного
текста (нужно 4.5:1), проходит только «крупный текст» порог (3:1), и то не всегда
(14px bold не всегда квалифицируется как «крупный»). Пара тёмной темы ("#0B1220 on
#DB9463") — **≈8.4:1**, с запасом проходит.

Это НЕ новая проблема — токен-пара `var(--accent)`/`var(--on-accent)` уже так используется
сайт-вайд в СВЕТЛОЙ теме: `.asst-bubble-user` (пузырь пользователя в Ассистенте),
`.obs-item--active`/`.mkt-item--active`/`.pf-item--active` (активный пункт тёмного рельса,
см. [[dark-rail-sidebar-family]]) и, вероятно, другие копперные CTA-кнопки. Везде одна и
та же лёгкая недостача контраста в светлой теме конкретно для этой пары.

**Why:** токен `--on-accent` в светлой теме — плоский белый, не подобран под реальный
контраст меди (которая довольно светлая сама по себе, ближе к средне-светлому оранжу, чем
к тёмно-синему `--accent-hover`). Это системное решение уровня `tokens.css`
(как и [[neo-dark-accent-token-gap]]) — не чинить точечно в одной фиче.

**How to apply:** используй `var(--accent)`/`var(--on-accent)` как обычно — консистентно
с остальным сайтом, НЕ делай точечный фикс (например через `color-mix` только в своём
компоненте) — это создаст РАЗНОБОЙ (одна кнопка контрастнее соседних без видимой причины).
Если owner спросит «почему текст на медной кнопке выглядит белёсым/менее читаемым» —
это причина; чинить — через `tokens.css` c явным ОК владельца (например, чуть притемнить
--on-accent в светлой теме, скажем до `#241005`/тёмно-медного, или добавить
`--on-accent-strong` отдельный токен только для крупных заливок с обычным текстом).
