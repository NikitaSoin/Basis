## Суть режима (гибрид «триггер + поводок»)
Агент НЕ переписывает барометр свободно и НЕ ежедневно (это развалило бы
экспертную калибровку G1-G13 за неделю дрейфом — предупреждение advisor).
Вместо этого:
- **триггер** от уже работающего `situation_overlay` (сенсор): alignment=
  противоречит → немедленная ревизия; ≥4 из 7 последних «сдвигает» по scope →
  ревизия; 30 дней без ревизии → плановая; cooldown ≥5 дней + кэп прогонов/мес;
- **поводок**: каждая авторевизия наследует экспертный якорь (баллы+rationale+
  anchor_note), обязана обосновать КАЖДОЕ изменение балла ссылками на статьи
  ленты; кумулятивный дрейф от экспертной версии ≤1.0 на субиндекс → freeze +
  эскалация «нужен экспертный пересмотр»;
- три слоя не конфликтуют: оверлей = ежедневная свежесть (без баллов),
  авто-ревизия = событийный пересбор баллов, эксперт = редкая переякоровка
  (квартал / по исчерпании поводка).

## Гейт качества (кодом, образец — macro_addendum_agent._gate), fail-closed
1. схема: 13 ключей, баллы ∈[1,5] шаг 0.5, вероятности сценариев Σ=1;
2. кэпы движения: |Δ|≤0.5 на субиндекс/ревизию, ≤4-5 субиндексов за раз,
   вероятности ±10 п.п.;
3. поводок: кумулятивный |дрейф| от якоря ≤1.0/субиндекс;
4. верифицируемое обоснование: delta_rationale со ссылками на id статей
   (гейт проверяет существование id); rationale нетронутых субиндексов —
   ДОСЛОВНЫЙ перенос (гейт диффает, агент не переписывает 42KB прозы);
5. комплаенс: тот же _BLOCKLIST + _GREY_SOURCES из situation_overlay.py;
6. без web-инструментов (только digest-статьи — анти-инъекция + контроль
   источников).
Провал → status=rejected, published-версия НЕ меняется; 3 rejected подряд → алерт.

## Персистентность
Таблица `BarometerVersion` (kind: geo|inst; source: expert|auto; status:
draft|published|rejected; parent_id; payload; trigger_reason; gate_notes).
🔴 Timeweb не пишет в git → барометр обязан жить в БД (файл агент персистентно
не обновит). Единый **read-path** `get_current_barometer(db)` для фронта,
оверлея И агента — иначе третий расходящийся слой (файл-якорь vs БД-ревизии).
`situation_overlay.py` (сейчас читает файл, строки ~51-53/107) перевести на БД.
Экспертный workflow цел: субагент пишет файл → git push → импорт при деплое
апсертит source=expert (паттерн asset_data.py) → поводок дрейфа обнуляется.

## Этапы
- **MVP (обратимо, ничего на бой)**: миграция барометров в БД + единый
  read-path + триггер-детектор от оверлея + агент-ревизор с гейтом в
  **SHADOW** (пишет draft, НЕ публикует). + плашка свежести на фронте
  («экспертная оценка от 12.07»; >35 дней → «оценка устарела»).
- **~2 недели shadow**: гендиректор смотрит drafts, ловит систематический брак.
- **Включение автопубликации** (🔴 требует явного ОК владельца на остаточный
  комплаенс-риск): пометка на фронте «автообновление от <дата> (модель),
  экспертный якорь от <дата>», сдвинутые баллы — тег «оценка (авто)».
- **Позже**: проза regions/summary; экспертная переякоровка по расписанию.
