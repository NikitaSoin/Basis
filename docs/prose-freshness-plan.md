## Постановка владельца (с уточнениями 2026-07-29)
- **Факты** (числа/даты и всё, что можно назвать фактом) → авто, **дневной крон**.
  Правим где число изменилось — **на ЛЮБОЙ вкладке** (вкл. гео/институты, если там
  устарело число). Не исключаем вкладки из дневной фактической сверки.
- **Интерпретация** (суждение) → **недельный крон**, по **ВСЕМ вкладкам**. НО:
  🔴 задача НЕ перегенерить заново — посмотреть, какой ВХОДНОЙ ПОТОК пришёл за
  неделю, и если что-то изменилось — поправить ТОЛЬКО в местах изменения; не
  изменилось — не трогать ничего (дельта-подход барометра).
- **Без черновика** — патчи сразу на бой (гейтованные), не draft-период.

## 🔴 Разворот advisor: «раз в сутки» ≠ «LLM ежедневно по всем»
Слепой ежедневный LLM 264×7 ≈ 1800 прогонов/ночь, ~160M токенов, десятки $/сутки,
95% вхолостую, риск повесить БД (прецедент в памяти), риск деградации прозы. НЕ делать.
**Правильно:** ежедневно — ДЕШЁВЫЙ КОД-ДЕТЕКТОР (без LLM) сверяет факты карточки с
живыми структурными данными → короткая ОЧЕРЕДЬ «где реально разошлось» (десятки/день);
LLM-патч запускается ТОЛЬКО по очереди. Свежесть та же, дешевле на 2 порядка (<$1/день),
безопаснее. Недельная интерпретация — тоже по триггеру (что пришло в поток), не по всем.

## Граница «биндить к живым данным vs LLM-патч прозы»
- **Биндить (live-чип, без LLM, факт НЕ устаревает):** показывать факт РЯДОМ с прозой
  как живой элемент (как уже с ценой/мультипликаторами). Топ-кандидаты: чип «ставка ЦБ /
  инфляция сейчас» в шапке вкладки Макроэкономика (одна на все 262 — самый массовый
  устаревающий факт), «последний отчётный период» на Финансах. Снимает ~80% видимого
  устаревания за копейки. **Внутри предложений число НЕ подменять** — «ставка снижена до
  14,5%, разворот к смягчению» с новым (выросшим) числом = ложь; факт-в-предложении
  правит LLM целым абзацем под гейтом.
- **LLM-патч (проза):** число/дата, вплетённые в утверждение. Проза уже размечена
  инлайн-тегами «(факт: …)» — готовые якоря для точечного патча и гейта.

## 🔴 Критично: файлы на бою ЭФЕМЕРНЫ
Проза — в git-файлах (companies/<T>/*.json, *_summary.md). Timeweb пересобирает
контейнер при деплое → серверный крон, правящий ФАЙЛЫ, потеряет правки при первом
redeploy и не умеет коммитить в git. Значит авто-патчи живут **версионным ОВЕРЛЕЕМ в БД**
(published/rejected/parent_id/откат, как agent_addenda/barometer_store). Фронт читает
«оверлей → фолбэк файл». Merge-back: периодически dev-сессия сливает оверлеи в репо;
будущий Opus-перепис стартует ОТ оверлея, не от устаревшего файла.

## Гейт v1 (fail-closed, кальки из barometer_reviser/card_consumer)
Обяз.: принудительный ДОСЛОВНЫЙ restore нетронутых абзацев кодом (не проверка —
перезапись, как `_restore_untouched_prose`); новое число обязано присутствовать в
триггернувшем структурном источнике (аналог `_mentioned_close`); сохранение
эпистемических тегов; кэп длины дельты; `_BLOCKLIST` + запрет «купить/продать»;
fail-closed (reject → старый текст живёт); маркер «обновлено ДД.ММ (авто)» на фронте.
Дневной проход правит ТОЛЬКО числа/даты внутри предложений (итоговые вердикты/абзацы —
read-only для него); недельный — абзацы (дельта, кэп доли изменённых).

## Риски
- **Шторм ставки:** одно решение ЦБ → ~262 макро-вкладки устарели разом. Смягчение:
  live-чип ставки (снимает срочность) + ночной кэп ~100-150 патчей по приоритету
  (трафик/ликвидность), очередь дотекает за 2-3 ночи.
- **Дубль с consumer:** consumer = аддитивная плашка «что произошло» (текст не трогает);
  этот механизм = целостность текста. Недельный проход ВПИТЫВАЕТ плашку в разбор и метит
  addendum поглощённым (supersede). Дневной патчер читает те же company_signals, чтобы
  не патчить только что освещённое.

## Этапы
**v1 (факты):**
1. Live-чипы ставка/инфляция (Макроэкономика) + отчётный период (Финансы) — дёшево, без LLM. ← начато
2. БД-оверлей прозы (модель + миграция) + read-path (фронт/API оверлей-first).
3. «Манифест фактов» для macro+finance+markets (~790 блоков) — разовый dev-прогон
   ЧЕРЕЗ Claude-субагентов (не DeepSeek, CLAUDE.md), извлечь проверяемые факты+якоря.
4. Дневной КОД-детектор: манифест vs живые данные + company_signals(high) → очередь.
5. Ночной LLM-патч очереди под гейтом. БЕЗ draft (владелец) — сразу published, гейт барьер.
**v2 (интерпретация):** недельный проход по триггерам (barometer should_revise-паттерн)
по ВСЕМ вкладкам от входного потока недели, дельта только в местах изменения; впитывание
плашек; merge-back оверлеев в репо.
**Не авто (пока):** полная перегенерация; ретрофит слотов в 1848 файлах.
