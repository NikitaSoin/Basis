# Источники ОТРАСЛЕВОЙ АНАЛИТИКИ — разведка лент для механизма новостной шины

> **Назначение.** Найти источники, откуда машина может РЕГУЛЯРНО забирать
> отраслевую аналитику (обзоры рынка, прогнозы, статистика с комментарием) —
> чтобы вкладки «Рынки» карточек компаний обновлялись свежим фоном СВОЕЙ отрасли.
> Механизм уже есть: конфиг источников → загрузчик RSS/WP-JSON → LLM-выжимка → БД.
>
> **Составлен:** 2026-08-08. **Метод проверки:** `curl -sSL --max-time 25` с браузерным
> User-Agent (Chrome/124, macOS) с дев-машины (НЕ российский IP). Фиксируется:
> HTTP-код после редиректов, размер тела, фактическое число `<item>`/`<entry>`
> и признак XML в первых 500 байтах. Заголовки первых записей выборочно читались
> глазами — чтобы отличить живую ленту от XML-заглушки.
>
> 🔴 **Правило реестра: ложный адрес хуже отсутствия.** Ничего не записано «по памяти»
> или «по аналогии». Где ленты нет — стоит `нет RSS` / `unknown` и указана HTML-страница.
>
> ⚠️ **Важно про IP.** Проверка шла с не-РФ IP. Часть международных сайтов
> (IEA, OPEC, worldsteel, mining.com, Fed) отдала `403`/`000` — это их антибот/CDN,
> с боевого Timeweb результат МОЖЕТ отличаться в обе стороны. Часть российских
> (peretok.ru, rosugol.ru) отдала `000` — вероятен обратный гео-блок, с РФ-IP
> они, скорее всего, живы. Отмечено в колонке «Проверено».

## Легенда

| Поле | Значения |
|---|---|
| **тип** | `rss` / `atom` / `json` / `html` (нужен парсер) |
| **периодичность** | день / неделя / месяц / квартал / событийно |
| **ПРОВЕРЕНО** | HTTP-код, размер тела, число записей. `000` = TLS/соединение не установилось |
| **прио** | 1 — ядро отраслевого фона; 2 — заметно усиливает; 3 — приятно иметь |

**Уже подключено в `news_sources.json`** (не дублировать): `angi.ru` (нефтегаз),
`tadviser.ru` (IT), `retail.ru` (ритейл), `ikar.ru` + `sovecon.ru` (агро),
`frankmedia.ru` (банки), `rusmet.ru` (металлургия), `thebell.io` (internal-only).
Ленты ниже — ДОПОЛНЕНИЕ к ним, с упором на аналитику, а не на новостную хронику.

⚠️ **Побочная находка: перепроверил уже подключённые ленты.** Живы `angi.ru`
(**200**, 60 793 Б, **50 item**), `rusmet.ru` (**200**, 18 555 Б, **12 item**),

Timeweb стоит: если и там `000`, агро-фон питается только `sovecon.ru`.

# 🔴 ЛОВУШКИ ПАРСЕРА — читать ПЕРЕД подключением

**1. Ложный 200 (адрес есть, ленты нет).** Такой источник молча отдаёт пустоту и
выглядит рабочим — ровно то, чего просил избегать владелец. Найдено 5 штук:

| адрес | что на самом деле |
|---|---|
| `https://www.metaltorg.ru/rss/news.xml` | HTML-страница 404 под кодом **200** (canonical → `404.metaltorg.ru`) |
| `https://bcs-express.ru/rss` | 1 577 Б HTML, 0 item |
| `https://icsg.org/feed/` | валидный RSS, но **0 записей** — пустая заглушка |
| `https://oilcapital.ru/rss` и `/feed/` | 13 602 Б HTML, 0 item |
| `https://rupec.ru/rss/`, `/rss.xml`, `/feed/`, `/export/rss.xml` | все отдают одну и ту же HTML-страницу 25 478 Б. 🔴 Рабочий адрес РУПЕК — **только** `/news/rss/` |

**2. `<dc:date>` вместо `<pubDate>`.** Все ленты **BIS** не имеют `<pubDate>` вообще —
дата лежит в `<dc:date>` (`2026-08-05T07:23:00Z`). Парсер, который ищет только
`pubDate`, проставит всем записям БМР дату загрузки и сломает хронологию.

**3. Мусорный HTML перед `<channel>`.** `https://www.so-ups.ru/rss/` вставляет
`<header class="ce-header">…</header>` между `<rss>` и `<channel>` и отдаёт
`Content-Type: text/html`. Строгий XML-парсер упадёт — нужна предочистка.

**4. Не отбраковывать по `Content-Type`.** `https://www.aex.ru/rss/` (150 записей) и
`https://www.so-ups.ru/rss/` объявляют `text/html`, но тело — валидный RSS.
Проверять по содержимому (`<rss`/`<feed` в первых 500 байтах), а не по заголовку.

**5. Разброс объёма огромный.** От 2 записей (`autostat/rss/4`) до 200 (`cnews`).
При `max_items_per_feed: 60` из `news_sources.json` крупные ленты (neftegaz 103,
bigpowernews 100, infranews 100, vgudok 100, aex 150, cnews 200, autostat 157)
будут срезаться — это нормально, но аналитические малые ленты
(`autostat/rss/4`, `comnews`) НЕЛЬЗЯ ставить в общую очередь с ними, иначе
дедупликация и importance-фильтр их вытеснят.

### 🔴 Л2. Ловушка: `Accept` в заголовках запроса ломает живую ленту

`fishnews.ru/rss` и `/rss_full` отдают **406 Not Acceptable** и НОЛЬ байт, если
в запросе стоит `Accept: application/rss+xml,application/xml,text/xml,*/*`
(им же я проверял все остальные ленты). Тот же адрес с дефолтным `Accept: */*` —
**200 и 25 записей**. То есть «мёртвый источник» здесь создаётся не сервером,
а нашим собственным заголовком.

🟢 **Для нас это не блокер:** `_HTTP` в `geo_digest.py` задаёт только `User-Agent`
и `Accept-Language`, заголовка `Accept` там нет — httpx подставит `*/*`, и лента
ответит 200. Но правило запомнить стоит: **если проверочный curl даёт 406/415 —
это, скорее всего, ваш `Accept`, а не мёртвая лента.** Перепроверяйте без него,
прежде чем записывать источник в отбраковку.

🔴 **Три вывода, которые дороже самих адресов:**
1. **`rel=alternate` — подсказка, а не доказательство.** Дважды за добор объявленный
   самим сайтом адрес оказался нерабочим: НРА отдаёт по своему `/feed/` HTML на 466 КБ,
   СовЭкон объявляет ленту комментариев вместо ленты статей (рабочая нашлась перебором).
2. **Формат даты — четвёртый способ ослепнуть.** `ict-online.ru` отдаёт 200, 109 записей,
   свежих — и все они пропали бы: `<pubDate>Friday, August 7, 2026 at 4:49:00 PM</pubDate>`
   наш `_parse_date` не разбирает, а без даты статья не публикуется. Проверять не только
   НАЛИЧИЕ даты, но и её ФОРМАТ.
3. **Живая лента ≠ полезная лента.** Восемь источников прошли ВСЕ технические проверки
   (200 / записи есть / дата свежая / формат читаемый) и отклонены по содержанию:
   `chemtech` (~15%), `adindex` (~20%), `bosfera` (~20%), `ifdc` (~20%),
   `plastinfo/rssf` (форум), `tfi` (~30%), `ict-online` (~30%), `d-russia` (~35%).
   Без просмотра реальных заголовков все восемь выглядели бы отличными кандидатами.
   Ещё два (`telesputnik` ~40%, `content-review` ~35%) прошли только в приоритет 3 —
   с оговоркой «низкий `max_per_run` + жёсткий importance-фильтр».
   И отдельно две ловушки свежести: `polymery.ru` (свежайшая 2019 год) и
   `nag.ru/rss/google` (60 записей, свежайшая апрель 2026) — обе с кодом 200.
