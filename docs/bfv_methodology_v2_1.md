## 2. Обязательные правки Н1–Н8

### Н1. Дисконтирование: spot против forward — жёсткий выбор

Два допустимых режима, смешивание запрещено:

**Режим SPOT (MVP):** DF_t(s) = (1 + z_t(s) + RP_i,t(s))^(−t), где z_t — бескупонная spot-ставка КБД на срок t. Никаких произведений.

**Режим FORWARD (целевой, для сценарных траекторий ключевой ставки):** DF_t(s) = Πτ₌₁ᵗ (1 + f_τ(s) + RP_i,τ(s))^(−1), где f_τ — однолетняя форвардная ставка между τ−1 и τ, извлекаемая из spot-кривой:

1 + f_τ = (1 + z_τ)^τ / (1 + z_{τ−1})^(τ−1)

Запрещено: подставлять z₁₀ как ставку десятого года в произведение (ошибка v2 в мастер-уравнении — исправлена). Сценарии, задающие траекторию ключевой ставки по годам, реализуются только в FORWARD-режиме. RP_i,τ = β_i·ERP (после Н8 — без остаточных надбавок).

### Н2. Банковский dividend capacity: CET1-мост без двойного счёта прибыли

Точная временная конвенция [Д]:

CET1_t^pre-dist = CET1_{t−1}^post-dist + EligibleProfit_t + OtherCET1Changes_t
RequiredCET1_t = TargetRatio_t · RWA_t
DividendCapacity_t = max(0, CET1_t^pre-dist − RequiredCET1_t)
CET1_t^post-dist = CET1_t^pre-dist − Dividend_t^paid

Прибыль входит в мост ровно один раз (в pre-dist), формула v2 «+ E_t − CET1·ΔRWA» упразднена. TargetRatio_t для РФ — не абстрактный CET1, а действующая регуляторика [Д, актуализировать]: нормативы Н1.0/Н1.1/Н1.2 + надбавка поддержания достаточности + надбавка за системную значимость (для СЗКО) + антициклическая надбавка + внутренний менеджмент-буфер; учесть регуляторные вычеты и действующие ограничения ЦБ на распределение (Permission-фильтр раздела 5.2 v2). RWA_t прогнозируются из кредитного роста (макро-драйверы), что замыкает связь capacity ← спрос на кредит ← макро.

### Н3. Фундаментальная динамика: прибыль, capacity, четыре класса удержанного

**Н3.1. Динамика прибыли — прямым счётом, не через g.**

E_{t+1} = E_t^legacy · (1 + MacroEffect_t − Decay_t) + ROE_incr_t · ProductiveReinvestment_t + r_cash · SurplusCash_t + ROE_waste · InefficientInvestment_t(накопл.)

g_t = E_t/E_{t−1} − 1 — вычисляемая диагностика, нигде не вход. Тождество g = b·ROE_incr — только интерпретация steady state и терминальная проверка (payout_L = 1 − g_L/ROE_L на выходе).

**Н3.2. Capacity — в рублях, через ёмкость выручки и капиталоотдачу.**

RevenueCapacity_{t+1} = TAM_{t+1} · Share_max_{t+1} − Revenue_t
ReinvestmentCapacity_t = RevenueCapacity_{t+1} / SalesToCapital_incr_t

SalesToCapital_incr — инкрементальная капиталоотдача (₽ выручки на ₽ нового капитала), из истории компании/сектора [Д]. Формула v2 «MarketGrowth·InvestedCapital + ShareGain» упразднена как размерностно нестрогая. Для банков capacity напрямую не задаётся — она следует из Н2 (RWA-рост, спрос на кредит, капитал, фондирование).

**Н3.3. Четыре класса удержанной прибыли (замена бинарного retention/diversion).**

Retained_t = ProductiveReinvestment_t + SurplusCash_t + InefficientInvestment_t; отдельно Leakage_t (diversion).

- ProductiveReinvestment = min(Retained_available, ReinvestmentCapacity) → работает под ROE_incr_t;
- SurplusCash → работает под r_cash (ставка денежного рынка/депозитов [Д]); sweep-механика: доходность кэш-корзины ежегодно направляется в распределение (сквозь те же π·m-фильтры), тело — буфер;
- InefficientInvestment (empire building, политический CAPEX) → ROE_waste < kₑ; доля определяется Capital Allocation Quality и governance-фактором 6 [Д, калибровка КТ-9]. Это третий класс, которого не хватало: невыплата без прямого tunneling всё равно может уничтожать стоимость через аллокацию;
- Leakage (diversion) — покидает периметр навсегда (willingness-причины, доля 1 − s_ben).

Правило аллокации benign-удержанного [Д]: сначала до потолка ReinvestmentCapacity → productive; сверх потолка → surplus cash; при плохом CAQ/госдирективах часть перенаправляется в inefficient (доля w_ineff из скоринга). Численно (пример, 10 раздел): перевод 40% benign-удержанного из ROE≈23% в r_cash=12% стоит ≈ −1% стоимости базового сценария — эффект материален и растёт с ухудшением CAQ.

### Н4. Buybacks: per-share режим — основной

Модель оценивает одну сохраняемую акцию, поэтому:
- Buyback НЕ входит в Dist_t (держатель, не продавший акции, кэша не получает);
- Эффект — через N_t = N_{t−1} − ΔN_bb,t и последующие EPS/DPS/BVPS; трансфер стоимости — через κ_bb = P_buyback/V_ps (выкуп ниже intrinsic — аккретивен оставшимся, симметрия κ эмиссий);
- Aggregate-режим (TotalDistribution = Dividends + NetBuybacks; VPS = PV/N₀) — только как отдельный readout-кросс-чек для buyback-ориентированных компаний, никогда не смешивается с per-share в одном расчёте. Флаг в конфиге движка: mode ∈ {per_share (default), aggregate_readout}.

### Н5. Residual income: whole-company, скоуп проверки, мосты сверки

RI считается на уровне всей компании, не на акцию:

EquityValue₀^RI = BV₀ + Σₜ DFₜ · (NI_t − kₑ,t · BV_{t−1}); VPS₀^RI = EquityValue₀^RI / N₀

Скоуп эквивалентности [Д]: строгая эквивалентность DDM ↔ RI доказуема на бессобытийной траектории (S ≡ 1, без leakage, κ = 1, clean surplus). Поэтому автоматическая проверка |V_DDM − V_RI| выполняется именно на этой траектории (движок прогоняет её отдельно, это дёшево); survival-adjusted RI НЕ считается эквивалентным survival-adjusted DDM без отдельного вывода (research-задача КТ-10).

Для полной модели вместо порога — таблица сверки:

V_DDM − V_RI = CleanSurplusBridge (OCI, переоценки, SBC) + DistributionRightsBridge (leakage, willingness-фильтры) + ShareCountBridge (эмиссии/выкупы при κ ≠ 1) + EventRiskBridge (различие survival-трактовок)

Каждый мост вычисляется и показывается; «ошибка» — только необъяснённый остаток моста, а не само расхождение.

### Н6. Competing risks: строгая нотация, тайминг, деклассификация делистинга

**Н6.1. Интенсивности → вероятности.** Первичны cause-specific интенсивности h_{j,t}. Тогда:

q_t^total = 1 − exp(−Σⱼ h_{j,t}); q_{j,t} = (h_{j,t}/Σⱼh_{j,t}) · q_t^total

Прямое сложение годовых вероятностей допустимо только как приближение при Σq < 5% и помечается в коде как approx-режим. Запрещено: механически складывать 10% + 15% + 5% = 30%.

**Н6.2. Тайминг событий θ_j ∈ [0;1].** Денежный поток года:

CF_t = S_{t−1} · [ (1 − q_t^total) · Dist_t + Σⱼ q_{j,t} · (θⱼ · Dist_t + R_{j,t}) ]

Дефолтные θ [Д]: дистресс θ = 0 (в год дефолта дивиденда нет); принудительный выкуп θ = 0.5 (зависит от отсечки); экспроприация θ = 0.5; при необходимости — полугодовая сетка событийного движка. S_t = S_{t−1}·(1 − q_t^total).

**Н6.3. Делистинг — не терминальное событие, а переключение режима.** Типология:
- добровольный делистинг с офертой → recovery = ожидаемая цена оферты (внешний якорь: правила 84.2/84.7, история оферт) — терминальное событие;
- технический делистинг с сохранением прав → НЕ absorbing: переход в состояние «неторгуемая», где продолжается PV распределений, но PositionExitValue получает скачок marketability-дисконта (раздел 3.7); права живут;
- потеря инфраструктурного доступа (санкционная) → recovery по юридическому сценарию (замороженная стоимость с дисконтом времени и исхода) [Д];
- банкротный делистинг → это дистресс, отдельного события нет.
Формула v2 «R^delisting = [0;0.4]·V_ps_pre» упразднена как циркулярная; там, где нужен якорь цены, используется MarketPrice^pre-event с явной оговоркой о предвосхищении рынком.

### Н7. Выходные диапазоны: честные ярлыки

- **Scenario quantiles:** дискретное распределение P(V = V_s) = p_s → квантили и P(V > цены) — можно публиковать как вероятностные при маркировке «при данных сценарных суждениях».
- **Sensitivity envelope:** решётка параметров БЕЗ весов → публикуется как «диапазон допущений», ярлыки P10–P90 запрещены.
- P10–P90 в строгом смысле — только при наличии весов на каждой точке (сценарии × параметрические распределения F_s(θ)) или после Монте-Карло (v3).

### Н8. Residual governance premium заморожен

В MVP: kₑ = z_t (или f_τ) + β·ERP_local. Точка. ResidualRiskPremium = 0. Немоделируемые governance-риски идут в: (а) ширину диапазона σ_V (через InformationQuality), (б) консервативный сценарий, (в) model-risk flag на карточке. Премия может вернуться только в форме β_Gov,i · FP_Gov с эмпирически оценённой факторной премией (новая КТ-11) — не как ручные 1–2 п.п. Побочный эффект: ставка упростилась и стала полностью объяснимой двумя наблюдаемыми компонентами.

## 3. Нормативные уточнения (остальные пункты)

### 3.1. Бета: без жёсткой винзоризации; τ² формально
Hard cap [0.4;1.8] исключён из методологии (низкобетовые utilities, золотодобытчики с отрицательной валютной чувствительностью, кризисные беты > 1.8 — реальны); остаётся только аварийный технический fallback с data-quality флагом. Контроль экстремумов — через robust-регрессию и постериорный вес. Сжатие: w_i = τ²/(τ² + SE_i²), где τ² = Var(β_i^true | sector) — априорная дисперсия истинных бет сектора; оценка методом моментов [Д]: τ̂² = max(0, Var(β_raw по сектору) − mean(SE²)). Двойное сжатие (Blume поверх) — запрещено, как и было.

### 3.2. ERP: shrinkage вместо фиксированных весов
ERP_t^used = w_t · π_t^implied + (1 − w_t) · ERP^long-run, где w_t ∈ [0;1] — скор качества implied-входов: покрытие дивидендных прогнозов индекса, доля спецдивидендов, концентрация индекса, стабильность терминальных допущений [Д]. ERP^long-run — историческая оценка (MCFTR − RGBITR) с широким CI. Якорь Дамодарана — не слагаемое, а диагностический коридор: выход ERP_used за пересчитанный в рубли коридор → флаг. Схема 0.5/0.3/0.2 упразднена.

### 3.3. Сценарные ставки: MVP-правило и усиленные проверки
MVP: ERP_s = ERP_base для всех состояний; по сценариям меняются только кривая z_t(s)/f_τ(s) и потоки. Сценарный ERP включается после калибровки КТ-5, с ограничением: амплитуда вариации ERP по состояниям существенно меньше амплитуды потоков. Проверки согласованности (обе обязательны): (1) Σₛ pₛ·ExpectedReturn_s ≈ z₁₀ + π ± 1.5 п.п.; (2) воспроизведение рынка: Σₛ pₛ·V_IMOEX(s) ≈ IMOEX₀ ± 10% [Д] — сценарная сетка, не воспроизводящая текущую цену рынка, внутренне противоречива (обычно — двойное наказание плохих состояний).

### 3.4. Адаптивный горизонт вместо «всегда 60»
Явный счёт: минимум 15 лет, максимум 50; остановка при одновременном выполнении: marginal PV(CF_t) < 0.1%·V; все параметры в δ-окрестности терминальных; TVShare хвоста < порога. Хвост закрывается терминальной формулой с сохранением хазардов: TV ≈ Dist·(1 − Σq)/(k − g + Σq·(1+g)) [Д]. Мотив: при k = 25% дальние годы — ничто, но в деэскалационном состоянии с k ≈ 12–16% вклад лет 30–50 материален, и фиксированные 60 лет создают ложную точность из 60-летних прогнозов hazard и институтов.

### 3.5. MoatValue — обязательный двойной расчёт
Всегда считаются V(s_L > 0) и V(s_L = 0); MoatValue = разница — публикуется отдельной строкой «стоимость рва» с обоснованием барьера (регулируемая монополия, сетевые эффекты, лицензии, IP) и секторным потолком s_L [Д]. Бесконечный положительный спред без явного барьера — запрещён. Это одновременно дисциплина и продуктовая фича («сколько в цене — за ров»).

### 3.6. Три уровня стоимости (замена бинарного intrinsic/marketability)
1. **FundamentalProRataValue** — доля в экономической стоимости бизнеса (движок без ликвидностных эффектов);
2. **TradableMinorityFairValue** — уровень 1 + права миноритария (EventRights уже внутри) + систематическая premia за ликвидность, если КТ-4 подтвердит её как priced factor (тогда в kₑ);
3. **PositionExitValue** — уровень 2 − market impact конкретной позиции (Amihud, спред, days-to-liquidate). Текущий Marketability-слой v2 — это уровень 3. Формулировка «ликвидность не меняет intrinsic value» уточнена: она не меняет уровень 1; уровень 2 может включать системную компоненту.

### 3.7. Реестр институциональных событий
EventID → {InstitutionalUpdates, ScenarioSignals, CompanyEvents} с классификацией каждого обновления: первичное (одно на событие на компонент), производное (вычисляется, не вводится руками), информационное (не меняет скоры). Правило: одно событие обновляет каждый компонент вектора I не более одного раза и только по первичному назначению — защита от размножения одного изъятия по PropertyRights, JudicialRisk, PolicyQuality, приорам и ERP одновременно. Реестр стыкуется с существующим новостным пайплайном Basis.

## 4. Каноническая вычислительная спецификация BFV-D (implementation-ready)

Конфиг движка: mode_df ∈ {spot, forward}; mode_dist ∈ {per_share, aggregate_readout}; T_min=15, T_max=50; ε_pv=0.001; список событий J = {distress, expropriation, forced_buyout} (+ regime-switch делистинга отдельно).

    # --- на каждое состояние s ---
    def value_scenario(s):
        BVc, BVcash, N = BV0, 0, N0
        E_legacy = E0; S = 1.0; PV = 0.0
        for t in 1..T_max:
            # ставки
            DF = spot: (1+z[t,s]+beta*ERP[s])**(-t)
                 forward: DF_prev / (1+f[t,s]+beta*ERP[s])
            # прибыль прямым счётом (Н3.1)
            E = E_legacy*(1+macro[t,s]-decay[t]) \
                + ROE_incr[t,s]*ProdReinv_prev + r_cash*BVcash + ROE_waste*Ineff_stock
            # распределение (Capacity -> Target -> факт), банк: Capacity из CET1-моста (Н2)
            Cap  = distribution_capacity(E, BVc, RWA[t,s], targets)      # Н2/Н3.2
            Targ = min(Cap, payout_policy[t]*E)
            Dist = Targ * P_permission[t,s] * P_willingness[t,s] * PayFrac[t,s]
            Short = Targ - Dist
            Leak  = Short * (1 - s_ben[t,s])                              # diversion
            Benign= Short * s_ben[t,s]
            Prod  = min(Benign + b_desired*E - ..., ReinvCapacity[t,s])   # Н3.2/Н3.3
            Cash  = surplus_rule(Benign - to_prod, CAQ)                   # -> BVcash
            Ineff = w_ineff(CAQ, gov6) * (Benign - to_prod - Cash)
            # акционерная арифметика + события эмиссий/выкупов с kappa (Н4)
            BVc   += E - Dist - Leak - Cash ; BVcash += Cash + cash_retained
            apply_issue_buyback_events(BVc, N, kappa)
            # событийный слой (Н6)
            q_tot = 1 - exp(-sum(h[j,t,s]))
            q[j]  = h[j]/sum(h) * q_tot
            CF = S * ( (1-q_tot)*Dist/N + Σ_j q[j]*( theta[j]*Dist/N + R[j,t,s] ) )
            PV += DF*CF ; S *= (1-q_tot)
            if t>=T_min and marginal_PV<eps and params_near_terminal: break
        PV += DF * S * Dist_next/N * (1-q_tot) / (k_L - g_L + q_tot*(1+g_L))   # хвост, 3.4
        return PV
    V0 = Σ_s p[s]*value_scenario(s)
    checks: RI_no_event_equivalence, bridges, TVShare, IMOEX_reproduction, Shapley, MoatValue

Recovery-якоря R[j]: distress → RecoveryRate·NAV_t (банкам ≈ 0); expropriation → α·BVPS_t; forced_buyout → β_price·MarketPrice_pre (закон 84.8, история занижений). Все — внешние к V (без циркулярности).
