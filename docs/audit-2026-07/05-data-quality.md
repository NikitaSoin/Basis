# Аудит данных Basis — свежесть, полнота, СТЫКИ

Дата: 2026-07-26. Область: `backend/companies/*` (264 папки), боевой API
`nikitasoin-basis-a772.twc1.net` (только GET). Один проход, данные не редактировались.
Скрипты аудита: `scratchpad/audit_data/` (freshness.py, joints.py, prices.py,
interim_flags_anomalies.py) — вне репо.

Контекст: прошлый аудит зафиксировал «платформа ломается на СТЫКАХ». Этот аудит
подтверждает вывод ЦИФРАМИ и находит главный механизм рассинхрона: **три источника
одной и той же справедливой цены** (файл / БД company_metrics / live-пересчёт),
из которых БД никогда не синкается автоматически.

## ТОП-10 системных проблем

### CRITICAL

**П1. Скринер и карточка показывают РАЗНУЮ справедливую цену: 239 из 252 компаний (95%), медиана расхождения 32%**
- Масштаб (замер на бою): расходятся >2% — **239**, >30% — **124**, >100% (в 2+ раза) — **24**.
- Механизм: карточка (decision-rail) берёт `financials.json → valuation.fair_value_range.base`
  + живую цену (`CompanyCardView.jsx:7185`); скринер/портфель берут `company_metrics.fair_value`
  из БД (`app/api/screener.py:115`), которую наполняет ТОЛЬКО ручной скрипт
  `scripts/sync_company_metrics.py` — он не вызывается ни из `start.sh`, ни из крон-джобов
  `app/main.py`. Файлы с 13.06 массово пересчитывались (валюация v2, чинка нестыковок),
  БД осталась на старых значениях.
- Примеры: DZRD файл 344 ₽ vs БД 3122 ₽ (скринер обещает апсайд +186%, карточка −68%);
  LSNGP файл 356 vs БД 16 (скринер показывает **−95% апсайда** по здоровой бумаге);
  GAZT 62.8 vs 1739 (+2669%); IGSTP файл 9100 vs БД 17198 → апсайд скринера +503%;
  VSMO 8700 vs 29580; MVID 35 vs 108.4 (апсайд +144% в скринере).
- Что сделать: вызвать `sync_company_metrics` в деплой-пайплайне / стартовом джобе рядом с
  `recalc_all_company_metrics` (main.py:95) и после каждой раскатки financials. Трудоёмкость **S**.

**П2. Коррупт `meta.last_price` → мусорные мультипликаторы на ЖИВЫХ карточках (подтверждено на бою)**

  отношением капитализаций от этой frozen-цены. Проверено на живом API:
