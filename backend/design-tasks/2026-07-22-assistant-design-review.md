Дата: 2026-07-22
Источник: inbasis.ru → Ассистент. Код: `frontend/Basis/src/AssistantView.jsx` (477 строк),
`frontend/Basis/src/styles/assistant.css` (578 строк), бэкенд-промпт синтеза ответа
`backend/app/services/assistant.py`, эндпоинты `backend/app/api/assistant.py`.
Скриншоты живого состояния: пустой диалог — `assistant_01.png`, диалог с одним

## Что я увидел

Экран технически исправен и уже частично на канонических токенах (Fraunces в
заголовках, IBM Plex Mono + tabular-nums в markdown-таблицах, медный `--accent`,
кремовый фон) — это НЕ история про «сломано», а про «сделано дёшево там, где
остальная платформа сделана дорого». Владелец прав, называя это «бедновато»: логотип
ассистента — это lucide-иконка `Sparkles` (обычная «звёздочка ИИ»), переиспользованная
6 раз без изменений формы; пузыри чата выглядят как дженерик-мессенджер, а не как
карточка Basis; эпистемические пометки («оценка Basis», «факт», «суждение») —
которые бэкенд-промпт ГАРАНТИРОВАННО кладёт в каждый численный вывод — на фронте
рендерятся голым текстом в скобках, а не визуальным тегом канона; сайдбар истории
диалогов — плоский список без единого признака той проработки, что есть у соседних
тёмных сайдбаров платформы (Обозреватель/Рынок/Портфель/Скринер).

## Что не работает (приоритизировано)

1. **[КРИТИЧНО]** Логотип/аватар ассистента — везде lucide `Sparkles`, самая
   клишированная «AI»-иконка в индустрии (тот же символ у ChatGPT, Gemini, Copilot,
   Notion AI). Она не несёт идентичности Basis и визуально говорит «это generic
   LLM-чат», а не «это аналитический инструмент Basis». Используется в 6 местах с
   4 разными размерами без единой системы:
   - `AssistantView.jsx:5` — импорт `Sparkles` из `lucide-react`.
   - `AssistantView.jsx:281` — `.asst-invite-icon`, `size={32}` (72×72 контейнер,
     `assistant.css:537-544`).
   - `AssistantView.jsx:358` — `.asst-head-icon`, `size={18}` (36×36, `assistant.css:223-233`).
   - `AssistantView.jsx:368` — `.asst-empty-icon`, `size={26}` (56×56, `assistant.css:438-445`).
   - `AssistantView.jsx:382, 393, 427` — `.asst-avatar` (аватар в каждом сообщении
     ассистента и в индикаторе «печатает»), `size={15}` (30×30, `assistant.css:262-272`).
   Почему плохо: у Basis уже есть свой узнаваемый знак — медная буква «B» в шапке
   (видна на обоих скриншотах, 40px левее). Ассистент — это ЛИЦО платформы в
   диалоговом формате, и сейчас оно ничем не отличается от любого стороннего
   чат-виджета, воткнутого в сайдбар.

2. **[КРИТИЧНО]** Эпистемические теги отсутствуют — они есть в данных, но не в UI.
   Бэкенд-промпт (`backend/app/services/assistant.py:207-208`) СТРОГО требует:
   «Каждое численное утверждение — с явной пометкой (факт с датой / оценка Basis /
   суждение), коротко в скобках» — то есть модель ГАРАНТИРОВАННО кладёт эту разметку
   в каждый ответ (см. `assistant_02_chat.png`: «...составляет **4,28** (оценка Basis
   на основе отчётности за 2025 год и цены на 16.05.2026)» и «...(оценка Basis)»).
   Фронт эту разметку никак не перехватывает — `ASSISTANT_MD` (`AssistantView.jsx:98-104`)
   задаёт рендереры только для `h1`/`h2`/`a`, обычный текст идёт как есть через
   `ReactMarkdown`. В итоге пометка тонет как серый текст в скобках внутри прозы —
   ровно то, для чего в каноне существуют `.bs-tag-fact`/`.bs-tag-estimate`/
   `.bs-tag-judgment` (`basis-design-system.css:94-97`, синий чип для «оценка»,
   медный чип-ромб для «суждение»). Это прямое нарушение обязательного принципа
   CLAUDE.md: «эпистемические теги на каждом аналитическом утверждении» — единственное
   место на платформе, где явно проговорённая эпистемика есть в тексте, но
   сознательно не визуализирована.

3. **[ВАЖНО]** Пузыри чата — форма дженерик-мессенджера, а не карточка Basis.
   `.asst-bubble-user` / `.asst-bubble-asst` (`assistant.css:274-293`) используют
   ассиметричный `border-radius: 16px 16px 4px 16px` / `4px 16px 16px 16px` —
   классический «хвостик» WhatsApp/Telegram/iMessage. Все аналитические карточки
   Basis (`.bs-card`, `basis-design-system.css:115`) — плоский прямоугольник с
   ОДИНАКОВЫМ радиусом (12px) на всех четырёх углах и 1px рамкой. Ответ ассистента
   про P/E Сбербанка сейчас визуально ближе к переписке в мессенджере, чем к выводу
   аналитического инструмента — при том, что по содержанию (таблицы, источники,
   эпистемика) это ровно аналитический вывод.

4. **[ВАЖНО]** Пустая лента после первого ответа — буквально пустой холст без
   функции и без бренда. На `assistant_02_chat.png`: единственный обмен репликами
   заканчивается на ~y=390px, а весь `.asst-shell` высотой ~870px — то есть НИЖЕ
   ответа ~480px чистого кремового фона до композера, вообще без единого визуального

   верху столбцом без заполнителя. Для чат-интерфейса верхнее выравнивание само по
   себе нормально (место копится под будущие сообщения), но полное отсутствие
   даже минимального фирменного акцента в этой зоне — именно то, что читается как
   «бедновато» рядом с плотными аналитическими экранами остальной платформы.

5. **[ВАЖНО]** Сайдбар истории диалогов заметно менее проработан, чем сиблинги.
   `.asst-side` (`assistant.css:85-191`) — светлый плоский список: без выделенной
   тёмной палитры, без decor-полосы слева, без группировки, активный пункт —

   (`observer-v2.css:9-149`, `market-sidebar.css:12-152`, тот же паттерн у
   Портфеля/Скринера по комментариям в файлах): отдельная тёмная палитра

6. **[НИЖЕ ПРИОРИТЕТ]** Иконка `<MessageSquare>` перед заголовком диалога в

## Что предлагаю (конкретно)

### Правка 1: заменить `Sparkles` на фирменный знак ассистента

Три конкретных, реализуемых чистым SVG/CSS варианта — без внешних ассетов, оба
поддерживают `currentColor` (наследуют цвет от текущих контейнеров
`.asst-avatar`/`.asst-head-icon`/`.asst-empty-icon`/`.asst-invite-icon`, менять их
фон/паддинги не нужно).

**Вариант A — переиспользовать брендовый знак (рекомендую по умолчанию).**
В шапке уже есть медный скруглённый квадрат с белой буквой «B» (виден на обоих
скриншотах, левый верхний угол). Найти компонент/класс, которым он рендерится в
шапке, и переиспользовать 1:1 в уменьшенном размере вместо `Sparkles` во всех
6 местах. Минимальный риск, максимальная отдача: ассистент сразу читается как
часть Basis, а не как воткнутый чат-виджет. Дальше в списке эта же метка
переиспользуется как водяной знак (Правка 4).

**Вариант B — знак «прицел/координаты» (инструментальная метафора).**

### Правка 2: визуальные эпистемические теги вместо текста в скобках

Бэкенд гарантированно кладёт паттерн `(факт ... / оценка Basis ... / суждение ...)`
в конце каждого численного утверждения (`backend/app/services/assistant.py:207-208`)
— это не случайная формулировка модели, а системная инструкция, поэтому парсинг
по規регулярке безопасен (не хрупкий edge-case, а гарантированный формат).

```jsx
// AssistantView.jsx — заменить объект ASSISTANT_MD (строки 98-104)
const EPISTEMIC_RE = /\((факт|оценка|суждение|модель)\b([^)]*)\)/gi;
const EPISTEMIC_LABEL = { факт: "ФАКТ", оценка: "ОЦЕНКА", суждение: "СУЖДЕНИЕ", модель: "МОДЕЛЬ" };
const EPISTEMIC_CLASS = {
  факт: "bs-tag-fact", оценка: "bs-tag-estimate",
  суждение: "bs-tag-judgment", модель: "bs-tag-estimate",
};

function withEpistemicTags(text) {
  if (typeof text !== "string") return text;
  const out = [];
  let last = 0, m;
  EPISTEMIC_RE.lastIndex = 0;
  while ((m = EPISTEMIC_RE.exec(text))) {
    if (m.index > last) out.push(text.slice(last, m.index));
    const kind = m[1].toLowerCase();
    out.push(
      <span key={m.index} className={EPISTEMIC_CLASS[kind]} style={{ marginLeft: 4 }}>
        {EPISTEMIC_LABEL[kind]}
      </span>
    );
    last = m.index + m[0].length;
  }
  out.push(text.slice(last));
  return out;
}

const ASSISTANT_MD = {
  h1: ({ children }) => <h3>{children}</h3>,
  h2: ({ children }) => <h3>{children}</h3>,
  a: ({ href, children }) => <a href={href} target="_blank" rel="noopener noreferrer">{children}</a>,
  p: ({ children }) => (
    <p>{React.Children.map(children, (c) => (typeof c === "string" ? withEpistemicTags(c) : c))}</p>
  ),
  li: ({ children }) => (
    <li>{React.Children.map(children, (c) => (typeof c === "string" ? withEpistemicTags(c) : c))}</li>
  ),
};
```
Нужно подключить `.bs-*` классы канона в скоуп ассистента (проверить, что
`basis-design-system.css` уже загружен глобально — если нет, самое узкое решение —
скопировать 4 нужных класса `.bs-tag-fact/.bs-tag-estimate/.bs-tag-judgment` в
`assistant.css` с теми же значениями, не изобретая новых цветов).

Нюанс: в промпте 4 категории («факт / оценка / суждение / модель»), а в каноне
3 CSS-класса (`bs-tag-fact/estimate/judgment`) — «модель» временно маплю на
`bs-tag-estimate` (ближе по смыслу: обе не сырой факт и не интерпретация). Если
продукту важно визуально различать «оценка» и «модель» — нужен 4-й класс в каноне
(`bs-tag-model`), отдельное решение владельца дизайн-системы, не в рамках этой
правки.

### Правка 5: сайдбар истории — обогатить, не копируя тёмный паттерн буквально

Важно: `.asst-side` — это НЕ навигационный рельс с фиксированным набором разделов
(как у Обозревателя/Рынка), а список переменной длины из пользовательского
контента (диалоги) — прямой перенос тёмной палитры сюда семантически неточен
(тёмный «инструментальный» рельс уместен для навигации, не для ленты записей).
Вместо копирования — точечные правки, поднимающие проработку до уровня остальной
платформы, но в своей (светлой) логике:

**5a — дата/время под заголовком диалога** (API уже отдаёт `updated_at`, ничего
менять на бэке не нужно):
```jsx
// AssistantView.jsx:320-340 — внутри .asst-conv, после <span className="asst-conv-title">
<span className="asst-conv-title">{c.title || "Без названия"}</span>
<span className="asst-conv-time">{formatRelative(c.updated_at)}</span>
```
```jsx
// хелпer рядом с остальными утилитами компонента
function formatRelative(iso) {
  if (!iso) return "";
  const d = new Date(iso), now = new Date();
  const days = Math.floor((now - d) / 86400000);
  if (days === 0) return d.toLocaleTimeString("ru-RU", { hour: "2-digit", minute: "2-digit" });
  if (days === 1) return "вчера";
  if (days < 7) return `${days} дн назад`;

}
```

## Оценка трудозатрат

- Правка 1 (замена иконки, 1 новый файл + 6 замен использования) — **S** (~1.5-2 часа,
  плюс решение по выбору варианта A/B/C — рекомендую согласовать с владельцем перед
  реализацией, т.к. это единственная субъективная развилка во всём документе).
- Правка 2 (эпистемические чипы) — **M** (~half day: парсер + проверка, что
  `.bs-tag-*` классы доступны в скоупе ассистента + ручная проверка на 5-10 реальных
  ответах разных типов вопросов).
- Правка 3 (форма пузырей) — **S** (10 минут, 2 строки CSS).
- Правка 4 (водяной знак) — **S** (~1 час, зависит от готовности Правки 1).
- Правка 5 (сайдбар: дата, border-left, иконка) — **S/M** (~2-3 часа, чисто
  фронтовая — бэк уже отдаёт `updated_at`, доп. работы на бэке не требуется).
- Правка 6 (моно-числа в прозе) — не оценивается отдельно, зависит от решения по
  промпту (не входит в объём фронтовой задачи).
- Правка 7 (постоянный триггер разбора документа) — **M** (~half day: нужен
  popover/modal-контейнер, которого сейчас нет в компоненте).

**Итого по документу: M (полдня-день)** для находок 1-5 (закрывают саму суть жалобы
владельца — «бедновато» + «логотип просто иишный»); Правки 6-7 — отдельный
последующий заход, не блокируют первую раскатку.
