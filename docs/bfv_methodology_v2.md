## 0. Позиционирование

### 0.1. Структура семейства

**BFV = BFV-Core + движки оценки.** BFV-Core — общая архитектура (ставка, права на распределение, состояния мира, институты, сборка, валидация) — инвариантна к движку. Движок — способ построить поток, на который у миноритария есть право. Этот документ описывает Core полностью и первый движок **BFV-D** (dividend/distribution engine). Прошлая v1 ошибочно позиционировалась как универсальная методика — принято.

### 0.2. Матрица выбора движка [Д]

| Тип компании | Основной движок | Кросс-чек |
|---|---|---|
| Банки, страхование | BFV-D + residual income readout | P/B × ROE регрессия |
| Зрелый плательщик (телеком, utilities) | BFV-D | FCFE, EV/EBITDA |
| Growth с ясной точкой выхода на выплаты | BFV-D с отложенным стартом выплат + RI | FCFE, EV/Sales дисциплина |
| Growth без видимых выплат | Residual income (та же рекурсия, readout RI) | FCFE |
| Сырьевые, циклические | Нормализованный FCFE (mid-cycle) | NAV по запасам, EV/EBITDA mid-cycle |
| Холдинги | SOTP (движки по сегментам) | дисконт холдинга к SOTP |
| Девелоперы | NAV | P/NAV сектора |
| Buyback-ориентированные | BFV-D c total distribution = дивиденды + чистые байбэки | FCFE |

BFV-D покрывает основную массу ликвидного российского рынка (банки, нефтегаз в режиме нормализации, телеком, utilities, металлурги-плательщики); остальные движки подключаются к тому же Core в v2–v3 очереди.

## 1. Принципы v2

**П1. Оцениваем права миноритария**, а не способность бизнеса генерировать поток. Между ними — три фильтра: способность распределить, разрешение распределить, желание распределить (раздел 5).

**П2′. Один экономический эффект — один механизм учёта.** Первичный шок (FX, ставка, санкции) легитимно действует на несколько величин через разные причинные каналы — это не двойной счёт. Двойной счёт — это когда один и тот же эффект проведён через два механизма (пример: срезали реальные потоки за инфляцию и одновременно дисконтировали номинальной ставкой заниженные потоки). Инструмент контроля — причинный граф шоков (6.1) + чек-лист (13).

**П3. Ставка — цена систематического риска; дискретные события — в потоках и вероятностях** (competing risks с recovery, раздел 5.4). Без изменений по сути, уточнено по границам.

**П4. Физическая вероятностная мера.** pₛ — физические (реальные) вероятности; сценарные потоки несут экономические последствия состояния; сценарные ставки — условные рыночные цены риска, а не «штраф за плохой сценарий» (4.5). Повышать ERP «для консервативности» запрещено; консерватизм живёт в явных допущениях потоков и однократно.

**П5. Intrinsic value отделена от реализуемости позиции.** Ликвидность бумаги не меняет pro-rata стоимость бизнеса — она меняет цену выхода конкретного держателя. Два слоя вывода: IntrinsicValue и MarketabilityAdjustment (раздел 9).

**П6. Прозрачность: диапазон + декомпозиция всегда;** точечная цифра без них не публикуется. Вклады блоков — устойчивые (Шепли, 10.3).

**П7. Совместимость** с существующими артефактами Basis (market_params.json, governance-скоринг и mapping, макро-методичка, 4-слойный сценарный инструмент) — сохранена; маршруты переопределены (см. миграцию 5.6).

## 2. Мастер-уравнение v2

Для состояния мира s, движка BFV-D, горизонта явного счёта T_ext ≈ 50–60 лет (терминальная формула — только для хвоста за T_ext, при kₑ ≥ 15% хвост < 1% стоимости):

**V₀ = Σₛ pₛ · Σₜ₌₁^{T_ext} DFₜ(s) · [ Sₜ₋₁(s) · Distₜ(s) + Sₜ₋₁(s) · Σⱼ qⱼ,ₜ(s) · Rⱼ,ₜ(s) ]**

- DFₜ(s) = Πτ (1 + k_τ(s))⁻¹ — дисконт-фактор по срочной структуре ставки сценария;
- Distₜ(s) — ожидаемое распределение миноритарию на акцию (дивиденд + чистый байбэк-эквивалент) из движка (раздел 3 и 5);
- qⱼ,ₜ(s) — хазарды конкурирующих терминальных событий j ∈ {дистресс, экспроприация/деприватизация, принудительный выкуп, делистинг-без-компенсации}, Rⱼ,ₜ(s) — recovery события j (якоря — 5.4);
- Sₜ(s) = Sₜ₋₁(s) · (1 − Σⱼ qⱼ,ₜ(s)) — выживание к концу года t; конвенция [Д]: распределение года выплачивается до реализации события года.

Ограничения согласованности (автопроверки): единая валюта и номинальный режим потоков и ставок; терминальная нормализация всех параметров (3.7); TVShare-диагностика (10.4); тождество g_L = ROE_L·b_L проверяется на выходе, не задаётся на входе.

## 3. Модуль A′ — фундаментальный движок BFV-D

### 3.1. Канон независимых переменных

Из тройки (ROE, b, g) независимо задаются ровно две; третья вычисляется. Никогда не задавать g напрямую — рост всегда выходной параметр экономики бизнеса.

**Режим S (simple, v2-дефолт):** задаются траектории ROE_t и payout_t → b_t = 1 − payout_t → g эндогенно из рекурсии.

**Режим A (advanced, целевой):** задаются доходность новых инвестиций ROE_incr_t и ёмкость реинвестирования Capacity_t; payout — остаток:

Reinvestment_t = min(b_t^desired · E_t, Capacity_t); payout_t = 1 − Reinvestment_t / E_t

Это точная формализация кейса Т-Банка: ROE может держаться, но возможность реинвестировать 70% прибыли под тот же ROE иссякает → payout растёт, g падает — без всякого принудительного затухания ROE.

### 3.2. Что именно затухает

Экспоненциальное (AR(1)) затухание применяется только к экономической величине — спреду доходности новых инвестиций над стоимостью капитала:

s_t = ROE_incr_t − kₑ,t; s_t = φ · s_{t−1}, 0 < φ < 1

Ссылка на Ольсона — аналогия по объекту (затухает abnormal return, не рост) [Ф]. Форма траектории g из этого НЕ выводится: g_t = b_t · ROE_incr_t, и если b_t тоже движется (а он движется), g не обязан быть экспонентой — и не должен.

Пресеты полураспада спреда [Д, калибровка КТ-3]: сильный ров/регуляторная защита 6–8 лет; норма 4–5; сырьё/цикл 2–3 (от нормализованного mid-cycle, не пика). Средний ROE книги затухает медленнее спреда новых инвестиций (старый капитал доезжает) — в режиме A это получается само; в режиме S аналитик задаёт ROE_t с этой оговоркой.

### 3.3. Capacity: ёмкость реинвестирования

Capacity_t = f(рост адресного рынка, достижимый прирост доли, регуляторные лимиты, M&A-пайплайн). Практическая параметризация [Д]: Capacity_t = MarketGrowth_t · InvestedCapital_t + ShareGain_t, где ShareGain_t → 0 на горизонте (доля не может расти вечно). Для банка Capacity дополнительно ограничена капиталом (3.4).

### 3.4. Distribution capacity (что бизнес способен отдать)

DistributionCapacity_t = f(FCFE_t; регуляторный капитал; ковенанты; юридические ограничения)

Для банков — обязательный блок [Д]: DivCapacity_t = max(0, CET1_t − CET1_target·RWA_t) + E_t − CET1_target·ΔRWA_t. То есть прогнозируются RWA (через рост кредитного портфеля из макро-драйверов), целевой буфер достаточности и только излишек распределим. Высокий ROE ≠ высокий распределимый поток при быстром росте RWA — модель обязана это видеть.

### 3.5. Полная акционерная арифметика

BV_t = BV_{t−1} + E_t − D_t^paid − Leakage_t + IssueProceeds_t − Buybacks_t + OCI_t
N_t = N_{t−1} + ΔN_issue,t − ΔN_bb,t; BVPS_t = BV_t/N_t; EPS_t = E_t/N_t

Допэмиссия сама по себе не разрушает стоимость: после размещения n акций по цене P_i справедливая стоимость на акцию V′ = (V_pre + n·P_i)/(N + n). Разрушение = размещение существенно ниже intrinsic (трансфер к покупателю/мажоритарию) или направление proceeds в проекты с ROIC < k. Моделирование [Д]: эмиссионные события задаются тройкой (вероятность; размер ΔN/N; κ = P_i/V_ps) — событийный движок применяет формулу трансфера, а proceeds попадают в BV и работают под ROE_incr. Постоянное «фоновое» δ из v1 упразднено как основной механизм (остаётся только для регулярных SOP-программ мотивации).

### 3.6. Второй readout: residual income на той же рекурсии

При clean surplus DDM и RI математически эквивалентны [Ф]:

V₀^RI = BVPS₀ + Σₜ DFₜ · Sₜ₋₁ · (EPS_t − kₑ,t · BVPS_{t−1}) − поправки на leakage/κ-события

Зачем считать оба: (1) RI переносит основную массу стоимости из терминала в BV₀ → структурно снижает TVShare; (2) расхождение |V_DDM − V_RI| — автоматический детектор нарушений clean surplus и ошибок арифметики; (3) RI — основной движок для неплательщиков (матрица 0.2) без отдельной инфраструктуры.

### 3.7. Терминальная нормализация (за пределами прогнозного окна T ≈ 10–15 лет, внутри явного счёта до 60)

К T нормализуются ВСЕ параметры, не только g: β_t → β_L (секторная долгосрочная), ERP_t → ERP_L, спред s_t → s_L ≥ 0 (для рва s_L > 0 допустим с обоснованием), payout_t → 1 − g_L/ROE_L (тождество — как проверка выхода). Терминальный g_L — по географии выручки [Д]: g_L,i = Σ_c RevShare_c · NominalGDPGrowth_c (для экспортёра — не российский ВВП), прирост доли рынка в пределе = 0. Хазарды qⱼ НЕ обнуляются в хвосте (пункт 11 ревью) — они входят в явный счёт до 60 лет; закрытая формула хвоста, если нужна: TV ≈ D·(1−Σq)/(k − g + Σq·(1+g)) [Д].

### 3.8. Санити-чеки: g_t < k_t после года 5; доля в отрасли/ВВП ограничена; payout ∈ [0;1]; для банков CET1 ≥ таргета во всех годах; при κ-событиях BV и N согласованы.

## 4. Модуль B′ — ставка

### 4.1. Формула

kₑ,i,t(s) = z_t(s) + β_i,t · ERP_local(s) + ResidualRiskPremium_i

z_t — бескупонная кривая ОФЗ (КБД) сценария; ликвидность ИЗЪЯТА из ставки в Marketability-слой (раздел 9); ResidualRiskPremium — только остаточный governance-компонент (5.6), cap 2 п.п. Правило «не добавлять CRP Дамодарана поверх ОФЗ + локальный ERP» сохраняется [Ф, зафиксировано и в market_params].

### 4.2. Implied ERP — спред над всей кривой

Решается относительно константы π:

IMOEX₀ = Σₜ E[Distribution_t] / (1 + z_t + π)^t (+ хвост)

π = ERP_local^implied. Это согласовано с тем, что и в оценке компаний дисконтирование идёт по z_t + премия. Триангуляция сохраняется: 0.5·π + 0.3·ERP_hist(MCFTR−RGBITR) + 0.2·якорь Дамодарана-в-рублёвой-системе [Д], границы 4–12%. Обязательные оговорки к π как индикатору [Ф/Д]: смена состава индекса, отраслевая концентрация (нефтегаз+банки), концентрация дивидендов в 5–7 плательщиках, префы, нерегулярные спецдивиденды, байбэки, survivorship. Поэтому π — «рыночная цена риска IMOEX», а не «премия российского бизнеса вообще»; для нетипичных компаний — секторные поправки через β.

### 4.3. Протокол беты

1. Регрессия избыточных полных доходностей: (R_i − R_f) = α + β(R_m − R_f) + ε; R_m — MCFTR (total return), акция — с учётом дивидендов; R_f — короткая ОФЗ.
2. Недельные данные, окно 3 года; Димсон (+1 лаг) для тонких бумаг.
3. Отчёт SE(β) и 95% CI — всегда; β без интервала не публикуется.
4. Сжатие к секторной бете (не к 1): β_post = w·β_raw + (1−w)·β_sector, w = σ²_sector/(σ²_sector + SE²) [Ф].
5. Запрет двойного сжатия: Blume НЕ применяется поверх байесовского сжатия.
6. Финансовые компании: Хамада неприменим (долг банка — сырьё) [Ф]; использовать секторную бету банков напрямую.
7. Винзоризация [0.4; 1.8] с комментарием при касании; терминальная β_L из 3.7.

### 4.4. Факторные решения (без изменений сути v1, уточнены формы): HML — не в ставку (двойной счёт с траекториями ROE/роста); RMW → Basis Resilience Factor → в Ability-хазарды и стресс-глубину потоков; CMA → Capital Allocation Quality → в выбор ROE_incr_L и κ эмиссий; size → потоки/BRF (доступ к капиталу, концентрация), НЕ отдельная премия; ликвидность → раздел 9.

### 4.5. Сценарные ставки в физической мере — дисциплина

Декларации: pₛ — физические вероятности; потоки сценария несут его экономику; z_t(s) — согласованная со сценарием кривая (калибровка сдвигов по эпизодам 2014/2022, КТ-5); ERP(s) — условная цена риска: оценка того, каким был бы implied π в этом состоянии (по тем же эпизодам), НЕ дополнительный штраф. Операционная проверка согласованности [Д]: средневзвешенная по pₛ ожидаемая доходность рынка из сценарной сетки должна попадать в окрестность текущей наблюдаемой (z₁₀ + π) ± 1.5 п.п.; выход за коридор = сетка внутренне противоречива (обычно — двойное наказание плохого состояния), пересобрать. Запрещено: менять ERP «для консервативности» (П4).

## 5. Модуль C′ — модель прав на распределение (EventRightsModel)

### 5.1. Три уровня распределения

DistributionCapacity_t (3.4) → TargetDistribution_t = Capacity-совместимый payout по политике → фактическая передача миноритарию:

E[Dist_t] = TargetDistribution_t · P(pay_t) · PaymentFraction_t

### 5.2. Декомпозиция вероятности выплаты

**P(pay_t) = P(Ability_t) · P(Permission_t | Ability) · P(Willingness_t | Ability, Permission)**

- Ability — экономическая способность: из FCFE/капитальной модели и BRF (долговая нагрузка, покрытие процентов, рефинансирование). Прогнозируется движком, НЕ governance-скорингом.
- Permission — регулятор/ковенанты/санкционно-юридические ограничения (для банков — надбавки ЦБ; для санкционных — техническая возможность платить в контуре).
- Willingness — воля контролирующего акционера. ТОЛЬКО сюда маппится governance-скоринг (факторы 5, 6, часть 4). Логистическая связка балл→P(Willingness) — сетка v1 сохраняется, но применяется к Willingness, а не к P(pay) целиком [Д, калибровка КТ-2 раздельно по причинам невыплат].

Следствие, устранившее системную ошибку v1: молодой качественный неплательщик получает низкий P(Ability выплатить сейчас), но высокие Permission/Willingness — и его нераспределённая прибыль остаётся в его BV (5.3), а не испаряется. Компания с историей ущемления получает низкий Willingness — и её невыплаты частично утекают. Это разные экономики, теперь модель их различает.

### 5.3. Retention vs diversion — центральное исправление v2

Невыплаченный дивиденд ≠ потерянный дивиденд. Учёт в ожиданиях [Д]:

- Shortfall_t = TargetDist_t − E[Dist_t] раскладывается на benign-часть (Ability/Permission-причины и добросовестная часть недоплат) и diverted-часть (Willingness-причины: вывод, tunneling).
- Benign-часть остаётся в BV_t и компаундится под ROE_incr (рекурсия 3.5 делает это автоматически: BV += E − Paid − Diverted).
- Diverted-часть = Leakage_t — навсегда покидает периметр миноритария.
- Split benign/diverted по причинам: Ability/Permission-невыплата → 100% retained; Willingness-невыплата → доля retained = s_ben ∈ [0; 0.7] по фактору 6 (госизъятие через «инвестиции» — частично retained с пониженным ROE_incr; прямой вывод — 0) [Д].

Численный эффект (сквозной пример, 10.2): переход от v1-семантики «невыплата = смерть потока» к retention/diversion поднял базовую оценку на +33%. v1 систематически занижала всех, у кого невыплаты вероятны по добросовестным причинам.

### 5.4. Competing risks и recovery без циркулярности

h_t^total = q^distress + q^expropriation + q^forcedBuyout + q^delisting — четыре раздельных хазарда со своими драйверами (BRF; институциональный вектор I; структура контроля >90–95%; инфраструктурно-санкционный профиль) и своими recovery, входят в мастер-уравнение (раздел 2) и НЕ обнуляются в терминале.

Якоря recovery — только внешние к fair value [Д]:
- R^forcedBuyout = цена по ст. 84.8 (нижняя граница закона: не ниже средневзвешенной за 6 мес. и цены оценщика) ≈ β_price · MarketPrice_pre-event; исторические кейсы занижения (Иркутскэнерго, СМЗ — уже в governance-методичке) → консервативный β_price 0.7–1.0 [Д];
- R^distress = RecoveryRate · NAV_t (ликвидационная логика), для банков часто ≈ 0 для акционера;
- R^expropriation = α · BVPS_t, α ∈ [0; 0.3] по институциональному вектору (PropertyRights, JudicialRisk);
- R^delisting-без-компенсации ≈ дисконтированная стоимость прав вне ликвидного рынка, практич. [0; 0.4]·V_ps_pre [Д].
Запрещено задавать R как долю рассчитываемой справедливой стоимости (циркулярность).

### 5.5. Эмиссии/выкупы как события: (вероятность; ΔN/N; κ = цена/intrinsic) — механика в 3.5; buybacks ниже intrinsic — положительный трансфер оставшимся (симметрия κ).

### 5.6. Миграция governance-маппинга: fallback v1 (всё в ставку) сохраняется при неполном скоринге; при полном — факторы 5/6/часть 4 → Willingness и s_ben; факторы 2/3 → κ-события и forcedBuyout-хазард; фактор 8 → InformationQuality → σ_V (ширина диапазона, 8.2) и частично ResidualRiskPremium ≤ 2 п.п. по перенормированным остаточным весам. Один флаг — один механизм.

## 6. Модуль D′ — макро через причинный граф

### 6.1. Причинный граф первичных шоков (замена жёсткого «один риск — один канал»)

Каждый первичный шок имеет задекларированный набор рёбер; учитывается каждое ребро ровно один раз. Примеры деклараций [Д]:
- FX → выручка экспортёра; FX → издержки импортозависимых; FX → инфляция → z_t (кривая) → kₑ; FX → инфляция → номинальный g_L. Всё это — разные эффекты одного шока, все легитимны одновременно.
- Ключевая ставка → z_t → kₑ; → стоимость фондирования банков (NIM); → кредитный спрос → рост портфелей; → процентные расходы закредитованных (BRF/Ability). НЕ добавляется отдельно «премия за высокую ставку».
- Санкционный пакет → дисконт Urals/логистика (потоки); → q^delisting/q^expropriation для затронутых профилей; → Permission (техническая возможность платить); → приоры Geo-блока. НЕ идёт напрямую в ERP — ERP сдвигается только на уровне состояния мира (4.5).
Инфляция — эталонный пример множественных легитимных рёбер (выручка, издержки, оборотный капитал, z_t, номинальный g_L) — и эталонный запрет: реальные потоки с номинальной ставкой.

### 6.2. Секторные драйверные уравнения — без изменений против v1 (банк/экспортёр/ритейл/utilities/IT), с добавкой для банков: LoanGrowth → ΔRWA → DivCapacity (3.4). Эластичности: OLS 2011–2025 с дамми разломов 2014/2022 или пост-2022 подвыборка [Г]; до оценки — секторные экспертные коэффициенты слоя 3 сценарного инструмента.

## 7. Модуль E′ — состояния мира

### 7.1. Иерархические блоки вместо монолитных сценариев

Под капотом состояние мира = комбинация независимо задаваемых блоков с условными связками:
- GeoRegime (деэскалация / статус-кво / эскалация / срыв) → санкционный профиль, приоры q-хазардов;
- MacroRegime (рост/инфляция/ставки/FX) с условным распределением P(Macro | Geo);
- CommodityRegime (нефть/металлы/дисконты) — частично независим от Geo (эскалация + дорогая нефть — валидная и важная для экспортёров комбинация);
- InstitutionalRegime (налоги/собственность/регулирование) — медленный, связан с Geo и I-вектором.
Параметры компании в состоянии = композиция блоков через прокси-факторы (слой 2 сценарного инструмента) и вектор экспозиции G_i. Четыре narrative-сценария сохраняются как UI-слой и MVP-редукция: каждый описан как задокументированная точка в пространстве блоков; для компаний с материальными «недиагональными» состояниями (экспортёр: эскалация×дорогая нефть) в сетку добавляется 5-й/6-й сценарий.

### 7.2. Вероятности: лог-odds обновление вместо эвристик

log(pₛ/p_base) = log(pₛ^prior/p_base^prior) + Σⱼ wⱼ · Signalⱼ,ₛ

Сигналы — чек-лист наблюдаемых маркеров по блокам + рыночные индикаторы (наклон КБД, вменённая волатильность валютных опционов, спреды) с явным признанием их коррелированности (веса wⱼ малы и не суммируют одну и ту же информацию дважды [Д]). До накопления статистики pₛ маркируются в продукте как «сценарное суждение», не как откалиброванная вероятность. Метрики качества: Brier, log-loss, calibration curve/reliability diagram — считаются с первого дня (КТ-6).

## 8. Модуль F′ — институты как вектор с закреплёнными каналами

### 8.1. Вместо скалярного ISI — вектор I_t = (PropertyRights, PolicyQuality, JudicialRisk, CapitalControls, Competition, InformationQuality), каждый компонент 0–100, квартально, экспертно-курируемо (источники — v1/раздел 8 + внутренние прокси изъятий/налоговых событий).

### 8.2. Жёсткая привязка каналов (защита от «суперфактора»):
- PropertyRights → q^expropriation и α recovery;
- PolicyQuality → потенциальный рост → g_L (российская компонента);
- JudicialRisk → recovery всех событий, β_price принудительных выкупов;
- CapitalControls → Marketability-слой (9) и ERP_L (медленно);
- Competition → s_L (терминальный спред) асимметрично по RentPosition (бенефициар/плательщик ренты);
- InformationQuality → σ_V — ширина публикуемого диапазона оценки и качество данных, НЕ ставка. (Идея «непрозрачность → неопределённость, а не доходность» — сохранена и усилена.)
Диагностика: отчёт эластичностей ∂V/∂I_k по каждому компоненту; суммарная институциональная чувствительность публикуется, аномалии (один компонент двигает V через 3+ канала) — флаг на разбор.

## 9. Marketability-слой (вынесен из ставки)

IntrinsicValue считается без премии за ликвидность. Отдельно: MarketabilityAdjustment = f(Amihud-иллюквидность |R|/Volume, bid-ask, доля нулевых доходностей, free float, days-to-liquidate для типовой позиции) → дисконт к позиции пользователя, показывается второй строкой («стоимость бизнеса» vs «реализуемость вашей позиции»). Дефолтные бакеты дисконта [Д]: высоколиквидные 0%; средние 3–5%; низколиквидные 8–15% + флаг. Опция после КТ-4: если премия за ликвидность подтвердится как priced factor на МосБирже — включаемый режим переноса части дисконта в kₑ; до тех пор — только слой поверх.

## 10. Сборка, пример, выходные форматы

### 10.1. Пайплайн v2 (12 шагов)

1. Профиль компании: движок по матрице 0.2; G_i; RentPosition; BRF; governance.json; сектор.
2. Кривая z_t, π (implied ERP), β по протоколу 4.3 → kₑ,t базового состояния.
3. Блоки состояний (7.1) → сетка из 4–6 состояний с pₛ (лог-odds, 7.2) и согласованными z_t(s), ERP(s) — проверка 4.5.
4. Движок: Capacity → Target → траектории E, BV, N по каждому состоянию (режим S или A).
5. EventRightsModel: Ability/Permission/Willingness → E[Dist], retention/diversion, κ-события.
6. Competing risks qⱼ(s) и recovery по якорям.
7. Явный счёт до 60 лет с терминальной нормализацией (3.7); мастер-уравнение (2) по каждому s.
8. V₀ = Σ pₛ V(s); RI-readout и |V_DDM − V_RI| проверка.
9. Диагностика: TVShare, отчёт эластичностей институтов, санити-чеки.
10. Shapley-декомпозиция вкладов блоков (10.3) + торнадо-чувствительность.
11. Выходное распределение: EV, медиана, P10/P25/P75/P90, P(V > рыночной цены) (10.5); Marketability-строка (9).
12. Кросс-чек вторым методом из матрицы 0.2; расхождение > 40% — ручное ревью; журнал допущений (снапшот всех входов).

### 10.2. Сквозной пример v2 (стилизованный банк, иллюстративно)

Входы как в v1-примере (BV₀=100; ROE₀=30% → ROE_L=22%, φ=0.87; payout 30%→84%; β=1.1; базовая k=25.0%), но семантика v2: P(Willingness)=0.94, PaymentFraction=0.95, s_ben=0.5; q^expropriation=0.5%/год с R=0.5·BVPS_t; состояния: деэскалация (p=0.20; k=19.75%; π_w=0.97; q=0.2%), база (0.55; k=25.0%), эскалация (0.25; k=30.2%; ROE_L=20%; π_w=0.88; PF=0.90; q=1.5%; s_ben=0.4). Отдельный «катастрофический сценарий» упразднён — экспроприация встроена как competing risk в каждое состояние.

Результаты: V(деэск)=151.7; V(база)=97.6; V(эскал)=60.5; **V₀ = 99.2 ₽** (на 100 ₽ книги). Диагностика: TVShare (вклад лет 16–60) = 12% — терминальная хрупкость структурно снята длинным явным горизонтом. Сравнение семантик: v1 давала base 73.6 / итог 72.7; переход retention-vs-diversion + recovery поднял базовую оценку на +32.7%. Урок: v1 систематически штрафовала добросовестные невыплаты как уничтожение стоимости; v2 наказывает только diversion и невозвратные события — дисконт стал адресным.

### 10.3. Декомпозиция вкладов: значения Шепли

Модель нелинейна → последовательный водопад зависит от порядка включения блоков. Вклад блока B = среднее по всем порядкам включения (Shapley) [Ф]: при 4–5 блоках (рост, EventRights, состояния, институты, marketability) это 16–32 прогонa модели — дёшево. UI остаётся водопадом, но числа устойчивы и суммируются в V₀ точно.

### 10.4. TVShare-диагностика: PV(хвоста за прогнозным окном)/V₀ > 75% — предупреждение; > 85% — «крайне чувствительная оценка»; > 90% — публикация только с отдельным пояснением. При явном счёте до 60 лет типичные значения 10–25%.

### 10.5. Выход — распределение, не min–max: [min V(s); max V(s)] не является вероятностным интервалом и не публикуется как «диапазон». Публикуются: EV, медиана по состояниям, P10–P90 (v2 — по сетке состояний × параметрической решётке ключевых допущений; v3 — Монте-Карло), P(V > текущей цены) с маркировкой «при данных сценарных суждениях».

### 10.6. Reverse-режим: рыночная цена объясняется множеством комбинаций (kₑ, g_L, t½, P(pay), ROE_L) — совместно неидентифицируемы. Реализация: implied-параметр по одному при фиксации остальных (меню: implied t½; implied kₑ; implied P(Willingness)) + 2D-поверхность V(kₑ, t½) как основная визуализация «что рынок должен думать, чтобы цена была справедливой».

## 15. Ограничения

Сохраняются ограничения v1 (короткая разорванная история, ненаблюдаемость части рисков, субъективность pₛ) плюс честные оговорки v2: ожидаемостная рекурсия — приближение (нелинейности до Монте-Карло усредняются грубо [Д]); физическая-мера сценарное дисконтирование — приближение к строгому SDF-ценообразованию [Д]; π IMOEX — индикатор рынка, не универсальная премия. Модель переводит суждения в цену дисциплинированно и показывает, какие суждения двигают результат; диапазон и Шепли-декомпозиция обязательны при любой публикации.
