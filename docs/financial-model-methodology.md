# Финансовые модели компаний — методика Basis (v1, пилот)

> Задача (владелец, 2026-07-26): «финмодель — это прогнозирование. Мы знаем,
> как компания зарабатывает, на что тратит и какие факторы на это влияют.
> Проходит время — хотим понять, что будет дальше: макрофакторы, цена товара,
> закупки, зарплаты, проекты, рост рынка → будущая выручка, EBITDA, чистая
> прибыль → будущие мультипликаторы → справедливая цена → куда скорее пойдут
> акции».

## Принципы (обратка гендиректора к видению владельца — что добавлено)

1. **Сценарии, не точка.** Один точечный прогноз всегда ошибочен и подрывает
   доверие. Модель даёт ТРИ траектории — база / бык / медведь — с явными
   допущениями каждой и вероятностной пометкой (суждение). Сценарии стыкуются
   с уже существующими слоями платформы: сценарной рамкой геополитики (S1-S4)
   и сценариями прогноза ЦБ.
2. **Драйверы с раскрытой механикой.** Не «выручка вырастет на 8%», а
   «выручка = объём × цена × курс; +10$ Brent → +X% выручки, потому что
   экспортная доля Y%». Каждый драйвер: источник текущего значения, связь с
   P&L, эластичность. Таблица чувствительности — обязательная часть витрины.
3. **Живые входы, статичная структура** (паттерн live_wacc.py — проверенный
   прецедент безопасной автономности). Аналитик-агент строит СТРУКТУРУ модели
   (драйверы, эластичности, базовые уровни) — редко. Движок пересчитывает
   ЧИСЛА от живых входов (Brent из фьючерса, ставка ЦБ, курс, инфляция — всё
   уже в БД) — на каждый запрос. Модель не протухает при движении рынка.
4. **Калибровка фактом.** Когда выходит новый отчёт (пайплайн интерима уже
   работает), факт сравнивается с прогнозом модели: отклонение публикуется
   честно («модель ждала X, вышло Y, разница Z% — причина») и структура
   пересматривается. Накопленная точность — сама по себе продукт доверия.
5. **Один источник правды.** Справедливая цена модели НЕ параллельна
   `valuation` карточки — модель постепенно СТАНОВИТСЯ источником forecast/
   valuation (сначала пилот живёт рядом с пометкой «модель v1, пилот», после
   обкатки — замещает). Не плодим расхождения между вкладками (главный вывод
   аудита платформы — ломается на стыках).
6. **Эпистемика.** Всё прогнозное — «модель/оценка», диапазоны вместо ложной
   точности, вероятности сценариев — «суждение». Без «купить/продать».

## Движок пересчёта (`backend/app/services/financial_model.py`)

На каждый запрос `/api/companies/{ticker}/financial-model`:
1. Читает `financial_model.json` (структура + базовые уровни).
2. Тянет ЖИВЫЕ входы: Brent (ближайший фьючерс BR из `futures`), USD/RUB
   (`spot_assets`/ЦБ-фид), ставка ЦБ (`macro_data_points`), инфляция.
3. Для каждого live-драйвера: отклонение живого значения от `base_value` →
   через эластичность корректирует прогнозные строки БАЗОВОГО сценария
   (бык/медведь не трогаются — они уже содержат свои уровни драйверов).
4. Пересчитывает форвардные мультипликаторы от ЖИВОЙ цены акции (quotes):
   forward P/E = цена / EPS_2026мод и т.д.
5. Пересчитывает справедливую цену и взвешенную по сценариям, апсайд от
   живой цены.
6. Отдаёт JSON витрине: сценарии, драйверы с текущими живыми значениями
   (и меткой «жив/база»), мост, чувствительность, track_record.

Барьер здравого смысла (как в live_wacc): если живое значение драйвера
отклоняется от base_value больше чем на 40% — пометка «структура модели
требует пересборки аналитиком», корректировка капируется (эластичности
линейны только локально).

## Сектор-шаблоны драйверов (пилот)

- **oil_gas (LKOH)**: Brent, USD/RUB, добыча/переработка, демпфер/НДПИ,
  инфляция OPEX. Метод оценки: forward P/E + дивдоходность (кросс-чек DCF).
- **banking (SBER)**: ключевая ставка → NIM (с лагом), рост кредитного
  портфеля, CoR (стоимость риска), опер. расходы/CIR. Метод: forward P/BV ×
  ROE (банковский стандарт платформы).
- **retail (X5)**: LFL-рост, открытие площадей, продовольственная инфляция,
  зарплатная инфляция (ФОТ-интенсивность). Метод: forward EV/EBITDA.

## Связь с существующими слоями платформы (ОБЯЗАТЕЛЬНО, не изобретать заново)

Карточка компании уже содержит числа и суждения, из которых модель обязана
исходить (и с которыми сверяться) — параллельная вселенная запрещена:

1. **Стресс-движок** (`stress_numeric.py`, `coefficients_payload`) — АБСОЛЮТНЫЕ
   чувствительности per компания с раскрытыми допущениями: fx (эффект +1₽/$ на
   выручку/EBITDA/ЧП, млрд руб), commodity (+1$), rate. Пример LKOH: +1₽ курса →
   выручка +41, EBITDA +12.3, ЧП +9.2 (нетто-ретенция ~30%, НДПИ/демпфер).
   Эластичности модели ДОЛЖНЫ быть согласованы с этими коэффициентами
   (пересчитай абсолютную чувствительность в %-эластичность и сверь; расхождение
   >30% — объясни в derivation, почему модель точнее, или исправь модель).
   Поле `cross_check_stress` в drivers[] — обязательное для fx/commodity/rate
   драйверов.
2. **macro.json** — каналы трансмиссии и направления (уже переиспользуется).
3. **geo.json** (`scenario_effects`) — сценарные эффекты war/peace через три
   канала (WACC/FCF/мультипликатор): использовать при построении бык/медведь
   сценариев и scenario_weights (бык часто = «перемирие», медведь = «эскалация»
   — бери оттуда согласованные величины эффектов, не выдумывай свои).
4. **institutions.json** — институциональная премия к требуемой доходности /
   дисконт мультипликатора: входит в обоснование target_multiple.
5. **governance.json** — дивидендная политика и история выплат → прогноз DPS.
6. **factor_exposures.py** — знаки коммодити-экспозиции (producer/consumer).

## Процесс

1. `financial-model-analyst` (субагент, Opus) строит/пересматривает структуру
   модели: драйверы, эластичности (с выкладкой!), сценарные уровни, базовый
   прогноз. Входы: financials.json (+interim), business_model.md, macro.json,
   market.json, свежие отчёты. Веб-поиск — гайденс компании, планы, консенсус.
2. Движок оживляет модель на каждый запрос (без LLM).
3. При выходе нового отчёта (чекер интерима уже ловит) — дописывается
   track_record, при большом расхождении — пересборка структуры аналитиком.
4. ОТК: card-critic смотрит согласованность модели с остальной карточкой
   (стыки!), персона — читаемость витрины.

## Ограничения v1 (честно)

- Эластичности линейные, локальные — большие сдвиги требуют пересборки.
- Баланс/ОДДС не прогнозируются постатейно в v1 (только FCF сводно) —
  полная 3-statement — v2, если пилот докажет ценность.
- Терминальная стоимость — через target multiple, не бесконечный DCF.
- track_record пуст на старте — доверие накапливается только временем.
