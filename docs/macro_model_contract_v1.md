# Контракт данных: макромодель компании и вкладка «Макроэкономика» (пилот, v1)

Этот файл — техническое приложение к двум методичкам владельца:
`docs/Макроэкономика_Финансовая_модель_v1.md` (как получать коэффициенты и прогноз по сценариям)
и `docs/Описание_вкладки_макроэкономика.md` (что выводится инвестору). Здесь зафиксирована
форма файлов, единицы и разделение труда: **аналитический агент задаёт входы, расчётный модуль
считает числа, агент-писатель собирает вкладку**. Арифметика внутри текста агентов запрещена
(спецификация вкладки, 0.5).

## 0. Решения владельца от 15.09.2026 (действуют поверх всего ниже)

- В сценариях Банка России участвуют только макроэкономические показатели: ключевая ставка, инфляция,
  рост ВВП и курс рубля (курс — достройка Basis, ЦБ его не публикует). Производные того же сценария
  (потребление, инвестиции, кредит, ипотека — из таблиц ЦБ; зарплаты, безработица — достройки) участвуют
  в расчёте, но инвестору как «условия сценария» показываются ровно четыре показателя.
- Цены на нефть и прочее сырьё/товары — не макроэкономика: в расчёте сценариев вкладки они зафиксированы
  на уровне базового периода (`excluded_variables` в `cbr_scenarios.json` + `scope: "financial_model"` у
  достроек компании в `scenario_inputs`). Их прогноз — область финансовой модели. Модуль отдаёт список
  зафиксированных переменных (`held_at_base`), вкладка объясняет это в `scenarios.held_at_base_note`.
- Горизонт вкладки — текущий и следующий год (2026 и 2027): `common_2026` (одинаков во всех сценариях)
  и `rows` — четыре строки за 2027, по одной на сценарий. Дальше двух лет не заглядываем.
- Слово «макро» отдельно не используется — везде «макроэкономика» / «макроэкономический …»;
  название пятого блока: «Как макроэкономика влияет на цену акции».
- Вкладка выводится на сайте: `GET /api/companies/by-ticker/{T}/macro-tab` (файл + паспорт расчёта `calc`),
  компонент `frontend/Basis/src/company/MacroeconomicsTab.jsx`; при отсутствии файла — прежний разбор.

## 1. Файлы

| Файл | Кто пишет | Что это |
|---|---|---|
| `backend/config/cbr_scenarios.json` | код/куратор (централизованно) | сценарии Банка России актуальной редакции + достройки Basis (курс, зарплаты, безработица) + значения базового периода и текущий спот. «Быстрые» данные (спец. 8.1) — общие для всех карточек |
| `backend/companies/<T>/macro_model.json` | агент-модельер (Opus) | четыре выходных объекта методики (Часть 13): профиль, набор коэффициентов (с модификаторами), входы для сценариев (достройки под компанию), паспорт достоверности. «Медленные» данные компании |
| `backend/companies/<T>/macro_scenarios.json` | расчётный модуль `app/services/macro_scenarios.py` | сценарные результаты, диапазоны, вклад входов, наиболее опасный сценарий, числовые привязки факторов, эффект ставки на стоимость. Пересчитывается кодом, руками не правится |
| `backend/companies/<T>/macro_tab.json` | агент-писатель (Sonnet) | шесть блоков вкладки по спецификации; числа берутся только из `macro_scenarios.json` и `macro_model.json` |

База прибыли для сценариев: модуль берёт `net_profit_base` (устойчивая база по методике 2.1, если
нормализованная прибыль карточки всё ещё несёт неповторяющиеся статьи — резервы, программы
акционирования, аномальную ставку налога), иначе `net_profit_adjusted`. Мост от нормализованной к
устойчивой базе — обязателен в `base_bridge` и показывается во вкладке в блоке «Как посчитано» рядом
с отчётным и нормализованным значениями (они должны совпадать со вкладкой «Финансы»).

Единицы: все денежные величины — **млрд руб.** (в `financials.json` карточки — млн руб.: делить на 1000).
Базовый период — последний полный отчётный год (сейчас 2025). Значения выручки и прибыли
обязаны совпадать со вкладкой «Финансы» (`financials.json`, поле `adjusted` для нормализованной прибыли).

## 2. Переменные сценариев (идентификаторы)

Из документа регулятора (`origin: "ЦБ"`), значения по годам как диапазон `{"low", "high"}`:

| id | Смысл | Единица |
|---|---|---|
| `key_rate_avg` | ключевая ставка, средняя за год | % годовых |
| `inflation_dec` | инфляция декабрь к декабрю | % |
| `inflation_avg` | инфляция в среднем за год | % |
| `gdp` | ВВП, прирост | % г/г |
| `consumption_hh` | потребление домохозяйств, прирост | % г/г |
| `gfcf` | валовое накопление основного капитала, прирост | % г/г |
| `exports_vol` / `imports_vol` | физический объём экспорта / импорта, прирост | % г/г |
| `money_supply` | денежная масса, прирост | % г/г |
| `credit_total` / `credit_corp` / `credit_hh` / `mortgage` | требования банковской системы к экономике / организациям / населению / ипотека, прирост | % г/г |
| `current_account` | счёт текущих операций | млрд долл. |
| `oil_tax_price` | цена нефти для налогообложения (близка к Urals), средняя за год | долл./барр. |

Достройки Basis (`origin: "допущение Basis"`, диапазон обязателен, происхождение описано в файле):
`usdrub_avg` (руб. за долл., средний за год), `real_wage` (реальная зарплата, % г/г),
`nominal_wage` (номинальная зарплата, % г/г), `unemployment` (безработица, %).

Переменные, которых нет в общем файле, но которые нужны компании (цена продукта, тариф,
скидка Urals к Brent, рост госзаказа, ставка ипотеки), агент-модельер добавляет в
`scenario_inputs` своего файла — по каждому сценарию и году, с диапазоном и происхождением.

Ключи сценариев: `base` (Базовый), `disinflation` (Дезинфляционный), `proinflation`
(Проинфляционный), `risk` (Рисковый) — названия берутся из файла, не задаются жёстко.

## 4. Объект коэффициента (методика 0.2 и 7.2)

```json
{
  "id": "fx_export",
  "label": "Курс рубля → экспортная выручка и прибыль",
  "macro_var": "usdrub_avg",
  "transfer_type": "direct",
  "per": "+1 руб./$",
  "effects": {
    "revenue":    {"base": 41.0, "low": 33.0, "high": 47.0},
    "ebitda":     {"base": 12.3, "low": 9.0,  "high": 15.0},
    "net_profit": {"base": 9.2,  "low": 6.5,  "high": 11.5}
  },
  "regimes": {"depends_on_regime": true, "current_regime": "жёсткая ДКП, крепкий рубль",
              "values_by_regime": {"высокая инфляция (перенос курса полнее)": {"net_profit": 10.5}}, "note": "…"},
  "thresholds": [ {"variable": "key_rate_avg", "condition": "above", "level": 18.0, "multiplier": 1.4,
                   "note": "выше 18% ипотека без субсидий останавливается — спрос падает быстрее"} ],
  "lag_quarters": [0.5, 0.3, 0.2],
  "asymmetry": {"up_multiplier": 1.0, "down_multiplier": 0.7, "note": "ослабление рубля переносится полнее укрепления"},
  "interactions": "чувствительность зависит от скидки Urals: при скидке выше $20 эффект курса на прибыль ниже на …",
  "origin": "выведено из структуры",
  "credibility": 2,
  "derivation": "экспонировано ~85% выручки (3200 млрд) / 80 руб. ≈ 41 млрд на 1 руб.; нетто-ретенция ~30% (закупка сырья и НДПИ/демпфер) → EBITDA ≈ 12; налог 25% → ЧП ≈ 9",
  "sources": ["src_2"],
  "modifiers_applied": ["geo_export_wedge"]
}
```

Правила:
- `effects.<строка>` — изменение строки отчётности в **млрд руб. на +1 единицу** переменной
  (для ставки, инфляции, роста, зарплат единица = 1 п.п.; для курса = 1 руб./$; для цен = 1 долл.;
  для переменных из `scenario_inputs` — единица, названная в них). Знак — по смыслу для компании.
- `low`/`high` — диапазон значения коэффициента (7.1: другие методы оценки задают диапазон;
  при коротких рядах — широкий). `base` обязан лежать внутри.
- Строки: минимум `revenue` и `net_profit` там, где эффект есть; `ebitda` — где применимо
  (у банков — `null`). Строка без эффекта не указывается.
- `origin` ∈ {«раскрыто компанией», «выведено из структуры», «оценено по истории», «принято допущением»};
  `credibility` 1/2/3 по 0.3.
- Особые случаи (7.3) **расщепляются на отдельные объекты**: банки — четыре объекта по ставке
  (переоценка активов, переоценка пассивов, объём выдач, стоимость риска); экспортёры с демпфером —
  курс на экспортную цену и на внутренние цены; застройщики — ставка на ипотечный спрос, на
  проектное финансирование, на счета эскроу; компании с кубышкой — ставка на процентный доход
  и на спрос. Единый коэффициент запрещён.
- `lag_quarters` фиксируется, но в расчёте вкладки не применяется (спец. 4.4: линейно, без лагов) —
  используется финансовой моделью.
- Модуль применяет: `effects × Δпеременной × asymmetry(по знаку Δ) × threshold multiplier(по значению
  переменной в сценарии)`, затем модификаторы.

## 5. Модификатор (методика Часть 9)

```json
{
  "id": "geo_export_wedge", "kind": "geo",
  "label": "Скидка к цене экспорта (санкционный клин)",
  "applies_to": "line:net_profit",
  "mode": "add_bn",
  "current": {"value": 17, "unit": "долл./барр.", "note": "скидка Urals к Brent, оценка сентября 2026"},
  "by_scenario": {"base": 0, "disinflation": {"low": 0, "high": 25}, "proinflation": {"low": -40, "high": -10}, "risk": {"low": -120, "high": -60}, "most_dangerous": -150},
  "origin": "принято допущением", "credibility": 3,
  "note": "как меняется скидка в сценариях регулятора, млрд руб. к прибыли относительно базового периода"
}
```
`mode`: `add_bn` — прибавка к строке (`applies_to: "line:<строка>"`), значения в млрд руб.;
`multiply_coef` — множитель к коэффициенту (`applies_to: "coefficient:<id>"`). Значение по сценарию —
число или диапазон. Отсутствующий сценарий = 0 (или множитель 1). Ключ `most_dangerous` — для
наиболее опасного сценария (10.4).

## 6. Что считает модуль (`macro_scenarios.json`)

Для каждого сценария и года из `display_years` (сейчас 2026, 2027, 2028; во вкладке — 2027 и 2028,
2026 у всех сценариев одинаков):
- Δпеременной = значение сценария (low/mid/high) − значение базового периода;
- по каждой строке: `base`, `low`, `high` (все входы в неблагоприятную / благоприятную сторону, 10.3),
  проценты к базовому году, вклады факторов (атрибуция), фактор-доминант, вклад входов в ширину диапазона;
- наиболее опасный сценарий — по `most_dangerous.adverse_values` и модификаторам с ключом `most_dangerous`;
- числовые привязки факторов: эффект «заметного» изменения переменной (курс ±10%, ставка ±1 п.п.,
  нефть ±$10, рост/инфляция/зарплаты ±1 п.п., кредит ±5 п.п.) на выручку и прибыль — для блока 2;
- эффект ставки на стоимость: ΔV/V на 1 п.п. ≈ −перенос/(r − g) по `valuation_link` (диапазон по переносу),
  плюс канал прибыли (коэффициенты ставки на прибыль / базовая прибыль) — для блока 5;
- проверки: строки согласованы (прибыль ≤ EBITDA ≤ выручка), |Δвыручки| > 40% → флаг «вне зоны
  линейности», убыток в диапазоне → флаг.
