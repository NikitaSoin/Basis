## Детали по пунктам задания

### 1. Мета-теги (проверено view-source: главная, /company/SBER/, /SBER/, /company/SBER/finance/, /company/SBER/geo/)

**Хорошо (не трогать):**
- Главная: title 63 зн., description продающий, canonical, og:* полный (с width/height), twitter:*, JSON-LD Organization + WebSite, `lang="ru"`, yandex-verification meta.
- Карточки: title/description **уникальны и с реальными числами** («Процентные доходы 2025: 3,56 трлн ₽, чистая прибыль: 1,71 трлн ₽» у SBER), canonical на себя, `robots: index,follow`, og/twitter, JSON-LD BreadcrumbList + Corporation, `lang="ru"`. Видимые хлебные крошки есть.
- Таб-страницы (finance/geo/macro/business/dividends): та же схема, h1 с типом раздела, honest-выжимки контента.

**Пробелы:**
- Нет FAQPage нигде (кандидаты: dividends- и fair-price-страницы — п.7/8 топа).
- Corporation JSON-LD без `sameAs` (сайт компании, e-disclosure) — слабее сущность.
- og:image один общий баннер на все 1577 страниц (og-banner.png отдаётся, 73 КБ) — допустимо, но перс. картинки с тикером/числом дали бы CTR в соцсетях.
- twitter:title/description на страницах компаний не дублируются (подхватится из og — некритично).

### 2. robots.txt и sitemap
- `robots.txt` отдаётся: `Allow: /` + ссылка на sitemap. Валиден. Можно добавить `Clean-param: company&tab` для Яндекса — CTA-ссылки `/?company=T&tab=X` плодят краул-дубли главной (canonical их склеивает, но краул-бюджет тратится).
- `sitemap.xml` отдаётся, валидный XML, **1577 URL** (2 служебных + 264 хаба + 1311 таб-страниц). Задача упоминала «~1577» — совпало точно.
- **lastmod нечестный** — у всех URL одна дата сборки (п.5 топа).
- Выборка 10 случайных URL: **10/10 → HTTP 200**, контент 7,7–13,3 КБ (не пустышки), без редиректов.

### 3. Яндекс
- Файл верификации `docs/yandex_a6dad74657642c4b.html` — **на бою в корне отдаётся (200)** + meta yandex-verification на главной. Вебмастер подключён (в шапке генератора v2 упомянуты «жалобы Яндекс.Вебмастера» — доступ есть).
- **Метрики НЕТ совсем** (п.3 топа). Единственный «counter» в грепе — внутренности maplibre-бандла.

### 4. Контент SEO-страниц (что видит бот без JS)
- Это **настоящие статические HTML**, не оболочки: h1, таблицы финансов по годам, дивтаблицы, ключевые факты, выжимки прозы ~3–3,5 тыс. знаков, перелинковка (хаб ↔ табы ↔ соседи по сектору ↔ каталог). Инлайн-CSS — статика рендерится мгновенно.
- Progressive takeover: страница дополнительно грузит бандл и при монтировании карточки прячет `#seo-static` (событие `basis:company-ready`, App.js:454). Для бота контент не меняется. Механика корректная.
- **Дублирования /company/X/ ↔ /X/ нет**: короткие /TICKER/ — noindex + canonical на /company/TICKER/ + meta-refresh. Сделано правильно.
- Каталог /company/ — полноценный хаб по секторам («Аналитика по 264 компаниям Мосбиржи»).
- Минус: **пользователь** из поиска на SEO-странице тоже качает 3 МБ несжатого main.js + 528 КБ CSS (п.1 топа).

### 5. Скорость
- main.js: **3 027 920 байт raw, сжатие сервером НЕ применяется** (перепроверено GET с `--compressed`: content-encoding отсутствует, size_download = content-length; сервер Caddy). Ожидаемые ~792 КБ gzip не достигаются — уходит все 3 МБ.
- main.css: 528 КБ raw, render-blocking.
- **Cache-Control нет ни на чём** (только ETag) — контент-хэшированные ассеты перекачиваются зря; надо `public, max-age=31536000, immutable` для /static/*.
- Первый рендер главной блокируют: main.css + 2 внешних Google-Fonts CSS (одна — легаси-шрифты, п.10). main.js — defer (хорошо). preload/prefetch отсутствуют (при self-host шрифтов добавить preload woff2).
- http→https 308 есть; /company → /company/ 308 есть.

### 6. Структура
- Перелинковка статики: хаб → 5 таб-страниц → друг на друга → «похожие компании» (до 8) → каталог → все хабы. Работает. Нюанс: «соседи» = первые 8 компаний сектора **по алфавиту** (`generate-seo-pages.js:808-810` `slice(0,8)`) — у всех компаний сектора один и тот же набор ссылок, вес распределяется неравномерно; лучше брать окно вокруг компании.
- **Разрыв: главная не ссылается ни на что** (п.2 топа) — граф статики висит без корня.
- ЧПУ приложения: в App.js **нет роутера вообще** (0 вхождений pushState/react-router). Скринер, облигации, Обозреватель (9 разделов), Портфель — без URL: не индексируются, не шарятся, не попадают в выдачу. Известная боль подтверждена. Deep-link только входящий: /company/T/slug/ и ?company=T&tab=X.
- Хлебные крошки: видимые + BreadcrumbList JSON-LD — есть везде в статике.

### 7. Генератор generate-seo-pages.js

- **Пропущенных компаний нет**: 264 директории с financials.json = 264 хаба в build/ (упомянутая в задаче «1 компания без financials.json» уже закрыта).
- **НЕ генерирует, а должен бы:** облигации (~3100 бумаг / ~639 эмитентов — крупнейший неиспользованный контентный актив, п.4), фонды (7 разборов готово!), фьючерсы, секторные страницы-подборки (/company/sector/…: «Нефтегаз Мосбиржи — сравнение»), fair-price-страницы (п.8), дивидендный календарь (данные отсечек в rates.csv есть).
- Качество кода: аккуратный (честная деградация, чистка обрезков md, cp1251-парсер, экранирование) — расширять безопасно.
- Локальный build/ отстаёт от боя (локальный hash main.73e878d8 ≠ боевой main.7694e77a — бой пересобран Timeweb'ом позже; это норма по модели деплоя).
