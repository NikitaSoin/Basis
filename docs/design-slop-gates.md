# Механические гейты против «ИИ-дизайн-шаблонности»

> Адаптировано из чек-листа Hallmark (github.com/Nutlope/hallmark, 58 slop-test gates) —
> Hallmark сделан для генерации лендингов из 20 визуальных тем, нам это не подходит
> (у Basis ОДИН канон — `basis-design-system.css`, не выбор темы под бриф). Взято отсюда
> только то, что годится для ЛЮБОГО интерфейса: механические, легко проверяемые «да/нет»
> гейты, которые ловят типичную ИИ-шаблонность ДАЖЕ когда токены/цвета формально верны.
>
> Используется: (1) `basis-designer` — самопроверка ПЕРЕД тем, как вернуть результат;
> (2) `basis-design-reviewer` — при ревью диффа, отдельным пунктом после проверки
> токенов/канона. Правило то же, что у Hallmark: **каждый ответ должен быть «нет»** — любое
> «да» это либо CRITICAL (ломает UX/доверие), либо WARNING (стоит поправить).

## Честность данных (для Basis — важнее всего в списке)
- [ ] Есть число/метрика, которая выглядит как факт, а на деле придумана/заглушка (не из JSON/API)?
- [ ] Есть текст-плейсхолдер («Загрузка…», «—», «TBD»), который остался в финальном рендере при наличии реальных данных?
- [ ] Дельта/тренд показан без эпистемического тега там, где это оценка/суждение, а не факт из БД?

## Повторяемость паттернов (то, что мы уже не раз чинили руками в этой сессии)
- [ ] Секция — это сетка из ≥6 визуально ОДИНАКОВЫХ плиток без ранжирования/акцента (сравни: почему
  «Обзор рынка» ушёл от сетки секторов к торнадо-диаграмме — направление+сила важнее ряда одинаковых чисел)?
- [ ] Два разных экрана продукта решают одну и ту же задачу (карточка/список/график) визуально по-разному
  без причины — не «два сайта разных студий»?
- [ ] Карточка добавлена ради карточки (рамка+тень+паддинг) там, где хватило бы строки в таблице?

## Контраст и читаемость
- [ ] Текст кнопки/чипа на цветной заливке не проходит контраст (особенно `--bs-copper`/акцент как ФОН
  под белым или бледным текстом — на меди частая ловушка)?
- [ ] В тёмной теме есть «text-on-text» — вторичный текст на слегка отличном тёмном фоне визуально сливается?
- [ ] Прозаический блок (`ANALYST_MD`, статьи, отчёты) шире ~75 символов в строке на десктопе?

## Микровзаимодействия / фокус / движение
- [ ] Hover есть, а focus-visible (клавиатурная навигация) — нет?
- [ ] Есть анимация/transition без учёта `prefers-reduced-motion`?
- [ ] Есть «празднующая» анимация значения (count-up, bounce, confetti) при ФОНОВОМ обновлении данных, не
  при первой загрузке (см. CLAUDE.md — «никаких празднующих анимаций», это уже наш принцип, гейт лишь
  механически его проверяет)?
- [ ] Disabled-состояние на кнопке визуально неотличимо от активного (только чуть светлее)?

## Мобильная безопасность
- [ ] Есть горизонтальный скролл всей страницы (не внутри отдельного `overflow-x` контейнера — таблицы/
  графики/код обязаны скроллиться СВОИМ контейнером, тело страницы — никогда)?
- [ ] Кликабельный текст (ссылка/чип) переносится на 2 строки с потерей области клика на части текста?
- [ ] Липкий (`sticky`) элемент перекрывает контент без отступа под свою высоту?

## Типографская дисциплина
- [ ] На экране больше трёх семейств шрифтов одновременно (канон — Fraunces/IBM Plex Mono/Inter, всё
  остальное — старьё или чужеродное)?
- [ ] Курсив используется в заголовке/лейбле там, где это не эпистемический маркер, а декор?
- [ ] Смешаны две библиотеки иконок в одном экране (канон — `lucide-react` везде; не подмешивать эмодзи
  как иконки-маркеры — тоже сюда, см. artifact-design skill)?

## Токен-дисциплина
- [ ] Цвет/радиус/тень подобраны «на глаз» в JSX (`style={{color:"#..."}}`) вместо `var(--bs-*)`/готового
  класса — даже если визуально близко к канону?
- [ ] Градиент использован не в данных (заливка area-графика), а в хроме — фон карточки/кнопки/хедера?

## Декор без функции
- [ ] Есть визуальный элемент (иконка/полоса/паттерн-фон), который ничего не сообщает о данных и не несёт
  функции — чистое украшение?
- [ ] Эпистемический тег (факт/оценка/модель/суждение) отсутствует там, где рядом есть похожий блок,
  где тег есть, — несогласованность, не отсутствие тега как принципа.

---

**Что осознанно НЕ портировали** из Hallmark (нерелевантно продукту с одним каноном, не лендинг-генератору):
выбор макроструктуры/темы под бриф, hero-обогащение (видео/Lottie), карусели, floating-nav, «study»
diversification knobs. Технику `hallmark study` (снять с референса структуру/типографику/цвет БЕЗ
пиксель-копирования — «не фотокопия, а диагноз: это Marquee Hero с моно-лейблами») — держим в голове как
приём, когда владелец кидает ссылку/скриншот понравившегося сайта: разобрать на роли (display/body/label,
цветовые band'ы, макроструктура), а не копировать хекс/шрифт 1:1 — и обязательно замапить результат на
`--bs-*`, никогда не тащить чужой hex в канон.
